# RainCough 面板

自托管的 Linux 运维面板。一个 Go 二进制监听一个端口，同时提供 HTTP API 和 Vue3 前端；
文件管理、终端、系统监控这些日常操作都在浏览器里完成，不依赖 SSH 客户端。

零第三方依赖 —— 没有 MySQL、没有 Redis、没有 Node 运行时、不调用外部命令。
`CGO_ENABLED=0` 静态链接，`ldd` 显示 `not a dynamic executable`，拷到任何一台
x86_64 Linux 上直接跑。

```
系统监控 · 文件管理 · Web 终端 · 插件扩展 · 面板自更新
```

---

## 一、形态

| 项 | 说明 |
|---|---|
| 后端 | Go 标准库，单文件静态编译 |
| 前端 | Vue 3 + Vite，构建产物内嵌进二进制 |
| 数据 | 文件形式存在 `data/` 下（KV log + JSON + 会话文件） |
| 扩展 | 插件独立进程，通过 UDS / loopback TCP 上的 JSON-RPC 通信 |
| 端口 | 单端口，HTTP 与前端同源 |

内置功能只有五项，边界很窄：**它是一台机器的操作台，不是一套运维平台**。
Docker、数据库、VPN、虚拟机这些不进主程序，需要就以插件形式挂上去，装卸互不影响。

## 二、部署

### 2.1 一行安装

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/fongwuyan/RainCough-panel-web/main/install.sh | bash
```

钉某个版本就把 `main` 换成 tag（tag 冻结，永久有效）：

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/fongwuyan/RainCough-panel-web/v1.0.0-beta/install.sh | bash
```

脚本走五步：确认 → 环境检查 → 插件运行时 → 下载主体 → 安装并验证。中途只会在
「是否开始」「root 密码（非 root 且非免密 sudo 时）」「是否固定静态 IP」「是否覆盖同名单元」
这几处停下来问，其余取默认。

### 2.2 安装后的样子

| 项 | 值 |
|---|---|
| 程序目录 | `/opt/raincough` |
| 数据目录 | `/opt/raincough/data` |
| 插件目录 | `/opt/raincough/plugins` |
| UDS 目录 | `/run/raincough` |
| 运行用户 | `root` |
| 服务单元 | `raincough.service`（`Restart=always`） |
| 端口 | 从 3900 起取第一个空闲（3900–3999）；重装时沿用原端口 |

### 2.3 登录

面板默认用**服务器自己的 SSH 密码**登录 —— 不需要再记一个密码。实现方式是用标准库
手写 SHA-512 crypt(3)，直接比对 `/etc/shadow` 里当前用户的哈希字段。

如果面板以非 root 运行（读不到 shadow），会自动降级到面板自带的 admin 密码：
安装时随机生成 32 字符，写入 `data/secret/admin.pw`（`0600`），同时打印到日志。

```bash
journalctl -u raincough | grep -i 'admin\|密码'
```

会话默认 30 天过期，cookie 名 `rc_session`，`HttpOnly` + `SameSite=Strict`。

### 2.4 安装参数

脚本化或离线部署时用环境变量：

| 变量 | 作用 |
|---|---|
| `RC_VERSION` | 指定版本，等价于用该 tag 的脚本 |
| `RC_ROOT_PASSWORD` | 免交互提供 root 密码 |
| `RC_ADMIN_PASSWORD` | 指定面板密码（省略则随机生成） |
| `RC_PORT` | 指定端口 |
| `RC_APP_DIR` | 覆盖安装目录 |
| `RC_RUN_USER` | 覆盖运行用户 |
| `RC_UNIT_NAME` | 覆盖单元名（多实例 / 测试隔离） |
| `RC_MIRROR` | 换下载镜像，默认 `gh-proxy` |
| `RC_PLUGIN_LANGS` | 要保证的插件运行时，默认 `python,php,java,node,go` |
| `RC_SKIP_RUNTIMES=1` | 跳过插件运行时安装 |
| `RC_NET_STATIC` | `yes`/`no`/`dry`，是否把当前网络写成静态配置 |

完全免交互：

```bash
curl -fsSL .../install.sh | RC_ROOT_PASSWORD='xxx' RC_ADMIN_PASSWORD='yyy' \
  RC_PLUGIN_LANGS=python RC_NET_STATIC=no bash
```

### 2.5 从源码构建

```bash
cd web && npm run release && cd ..     # 前端 → public/
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags "-s -w" -o dist/raincough ./cmd/raincough
```

`tools/pack-release.sh` 把这两步加上打包、行尾校验、版本一致性校验串起来，产出
`dist/raincough-linux-x86_64-<版本>.tar.gz`。

## 三、功能

侧边栏固定五项：**工作台 / 文件管理 / 终端 / 插件 / 设置**。
面板更新是常驻浮层，挂在标题右侧，不占条目。

### 3.1 工作台

进入面板后的默认页，一屏看完这台机器的状态。

**概览**：主机名、系统与架构、运行时长、启动时刻、Go 版本、进程与线程数、交换分区。

**实时指标**：CPU 每核利用率网格、内存占用、磁盘总览与各挂载点用量、网络上下行
（总量 + 分接口累计）、Load Average、GPU（显存 / 利用率 / 温度，检测不到就留空）。

**趋势**：服务端每秒采样一次，前端画最近一段时间的曲线，刷新页面不丢历史。

**任务队列**：工作台里的一张卡片，列出正在跑的长任务（打包、批量复制、插件安装）及进度，
最多显示 5 条。

### 3.2 文件管理

浏览器里的双栏文件管理器，按目录浏览，支持收藏夹和磁盘切换。

| 操作 | 说明 |
|---|---|
| 上传 | 分片上传（8MB/片，带进度）；同名冲突可选覆盖、重命名或跳过 |
| 下载 | 单文件直连；多选打包成 zip 后下载 |
| 编辑 | 文本文件在线读写（UTF-8） |
| 整理 | 新建目录、重命名、删除、复制、移动、压缩 |
| 解压 | zip（tar / gz 用终端里的系统工具） |
| 校验 | 计算哈希 |
| 统计 | 目录体积统计 |
| 搜索 | 关键字搜索当前目录，结果可分页加载 |
| 预览 | 图片、文本直接看 |

复制、移动、压缩这类耗时操作走异步任务，可以离开页面，回来在任务队列里看结果。

### 3.3 终端

基于 PTY 的 Web 终端，打开就是一个真实的 shell，不是命令回显模拟。

- 多会话并行，每个标签独立 PTY
- 断线重连保留会话
- **主机管理**：保存常用 SSH 目标（名称 / 地址 / 端口 / 用户 / 密码），一键连接
- **常用命令**：把高频命令存成快捷按钮，点一下发到当前会话

### 3.4 插件

面板本身只有五项功能，其余能力通过插件扩展。插件是独立目录 + 独立进程，
通过 JSON-RPC 与主程序通信，崩了不影响面板，装卸不重启面板。

插件页提供：

- 已安装列表（版本、语言、运行状态、接口数）
- 插件市场（配置仓库地址后浏览、安装、更新、卸载）
- 上传安装（`.zip` / `.tar.gz` / `.tgz` / `.tar`）
- 单个插件的服务控制（启动 / 停止 / 重启 / 开机自启）与日志
- 运行时体检（本机 python / php / java / node / go 是否就绪）

插件的前端产物由主程序托管，插件自己不用起 Web 服务。

### 3.5 设置

| 分组 | 内容 |
|---|---|
| 外观 | 深色 / 浅色主题 |
| 仓库 | 插件仓库地址、面板仓库地址 |
| 任务记录 | 清理已完成任务 |
| 环境 | 面板版本、构建提交、Go 版本、程序目录、数据目录、运行时长 |

### 3.6 面板更新

侧边栏标题右侧常驻一个更新浮窗，三步手动，不静默升级：

1. **检查** —— 比对当前版本与仓库最新 Release
2. **下载并应用** —— 下载新资产、校验、替换二进制（旧版本留一份备份）
3. **确认重启** —— 弹窗询问是否立即重启，取消就下次生效

升级出问题可以在同一浮窗里**回滚**到上一份备份。整个过程有日志可查。

## 四、运行

### 4.1 服务

```bash
systemctl status raincough        # 状态
systemctl restart raincough       # 重启
journalctl -u raincough -f        # 实时日志
journalctl -u raincough -n 200    # 最近 200 行
```

单元文件里定死了工作目录和环境变量，改端口就改 `ExecStart` 里的 `-port`。

### 4.2 目录布局

```
/opt/raincough/
├── raincough            主程序（前端已内嵌）
├── public/              前端产物，随包附带
├── data/                数据（KV log、会话、插件配置、上传临时文件）
│   └── secret/          admin 密码
├── plugins/             插件目录，每个插件一个子目录
├── install.sh
└── VERSION
```

备份只需要 `data/` 和 `plugins/`。主程序和 `public/` 可以从 Release 重新获取。

### 4.3 环境变量

单元文件里已经设好，一般不用动：

| 变量 | 说明 |
|---|---|
| `RC_DATA_DIR` | 数据目录 |
| `RC_PLUGINS_DIR` | 插件扫描目录 |
| `RC_UDS_DIR` | 插件通信的 socket 目录 |
| `RC_ADMIN_PASSWORD` | 覆盖面板密码（明文，只在内存，不落盘） |
| `RC_PORT` | 端口（也可以命令行 `-port`） |

插件相关的 `RC_PLUGIN_*` 一组由主程序在拉起插件时注入，不需要手工配置。

### 4.4 迁移

```bash
# 旧机
systemctl stop raincough
tar czf rc-backup.tgz -C /opt/raincough data plugins

# 新机（先跑 install.sh 装好）
systemctl stop raincough
tar xzf rc-backup.tgz -C /opt/raincough
systemctl start raincough
```

会话、插件配置、任务历史都在 `data/` 里，迁完登录状态还在。

### 4.5 卸载

```bash
bash /opt/raincough/uninstall.sh          # 删程序，保留 data/ 与 plugins/
bash /opt/raincough/uninstall.sh --purge  # 连数据一起删
```

默认保留 `data/` 和 `plugins/` —— 重装后登录状态、插件配置、历史都还在。

## 五、接口与鉴权

主程序对外暴露 51 条 `/api` 路由，分六组：

| 前缀 | 内容 |
|---|---|
| `/api/system` `/api/disks` `/api/net/status` `/api/workspace/history` | 系统信息、磁盘、网络、性能历史 |
| `/api/fm/*` | 文件管理（列表、读写、分片上传、异步操作、解压、统计） |
| `/api/terminal/*` | PTY 会话、主机、常用命令 |
| `/api/plugins/*` `/api/services/*` `/api/interfaces/*` | 插件、服务控制、接口注册表 |
| `/api/store/*` | 插件市场（仓库、安装、更新、上传） |
| `/api/panel/*` `/api/tasks/*` | 版本与更新、任务队列 |

登录相关是 `/api/auth/login`、`/api/auth/status`、`/api/auth/logout` 三条，由鉴权中间件
单独注册，不在这 51 条里。

鉴权是 session 中间件：除了这三条、`/login` 和静态资源，其余接口全部要求有效 session，
未登录一律 401。

插件接口额外有一套调用入口，`POST /api/interfaces/<id>/invoke`，请求体是
`{"params": {...}, "timeout_ms": N}`，参数必须放在 `params` 里。

## 六、技术取舍

**为什么坚持零依赖。** 面板是管理入口，它自己不能成为需要被管理的东西。
带 MySQL 的面板，数据库挂了面板就打不开；带 Node 的面板，升级 Node 可能把面板搞坏。
标准库能覆盖的部分全部自己写：HTTP 服务、会话、SHA-512 crypt、KV 存储、进程守护。

**为什么功能这么少。** 内置功能每多一个，主程序的维护成本和出错面就大一圈。
Docker 面板、数据库管理、VPN 这些用插件做，装不装、升不升、崩不崩都和主程序无关。

**为什么更新要手动三步。** 面板是唯一入口，自动升级失败意味着再也进不去。
所以检查、应用、重启分成三步，每步都要人点，失败还能回滚。
