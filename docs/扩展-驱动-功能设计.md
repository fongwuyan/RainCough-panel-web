# 系统扩展「驱动」功能设计（v1）

> 配套文档：[扩展-驱动-设计方案.md](扩展-驱动-设计方案.md)（v3 实施设计：机制契约、9 个接口、命令模板、护栏、分期验收）。
> 本文只写**功能**：页面上有什么、点下去发生什么、各种状态下显示什么、文案是什么。
> 机制与接口细节以 v3 为准；本文需要的两处接口补充已同步进 v3（`overview.pending`、`task` 列表模式）。

界面规矩（沿用面板既有硬要求，本文所有设计都遵守）：

- 内置功能页**不写页头标题**；本页四段直接进内容，**不用页内选项卡**（单页滚动）。
- **不写静态提示语/操作指引**；页面上只允许出现：数据、状态、风险说明、确认要求。
- 直角（`--radius*` 全 0）、文字按钮、无 emoji、无图标字体；中文文案，术语保留原文（modprobe / DKMS / initramfs / MOK）。
- 复用现有全局样式：`.page` `.page-body` `.section` `.section-title` `.table` `.btn` `.btn-sm` `.btn-primary` `.btn-danger`
  `.input` `.select` `.tag-chip` `.status-line` `.mono-block` `.progress` `.hint` `.empty` `.error` `.form-row`；
  颜色只用变量（`--text` `--text-muted` `--text-faint` `--surface-2/3` `--border` `--accent` `--danger` `--success`）。

## 三、逐区块功能详述

### 3.1 体检（只读）

**F-01 摘要行 + 刷新**
- 元素：`[刷新]`（`.btn .btn-sm`，请求中显示「刷新中…」并禁用）；一行等宽摘要：`内核 <kver> · <发行版> · <架构> · Secure Boot <开/关> · DKMS <已装/未装> · headers <已装/未装>`。
- 行为：进页面自动取一次（接口侧 5s 缓存）；点刷新带 `{refresh:true}` 绕缓存。
- 边界：采集超时（20s）→ 摘要行显示「体检超时」+ `[重试]`；部分项失败 → 该项显示 `-`，不整页失败。

**F-02 复制体检报告**
- 元素：`[复制体检报告]`。
- 行为：把当前体检快照按固定文本模板（系统/工具/设备表/固件/问题）拼成纯文本写剪贴板；成功短暂显示「已复制」1.5s 后复原（不是提示语，是操作结果）。
- 用途：出问题时发给别人看；不涉及任何接口。

**F-03 设备表**（`.table`）
- 列：`总线` `地址` `类别` `名称` `驱动` `版本` `固件` `状态` `[详情]`。
- 排序：**未绑定优先**，其次类别（显示 > 网络 > 存储 > 其它），再按地址。
- 状态列：`已绑定` / `未绑定`（`.tag-chip`）；驱动列显示模块名（等宽），未绑定显示 `—` 并在该行右侧给 `[查候选模块]`（跳 F-12 并预填设备地址）。
- 固件列：`正常` / `缺 <文件名>` / `—`（无固件需求的设备）。
- 实测预期（宿主）：`0000:00:02.0 / 0300 显示 / Intel HD Graphics 5500 / i915 / 6.1.0-52-amd64 / 正常 / 已绑定`；
  `0000:03:00.0 / 0200 网络 / RTL8111/8168/8411 / r8169 / … / 正常 / 已绑定`。

**F-04 设备详情**（行内展开，不弹窗）
- 内容：完整 ID（`vendor:device` / USB `vid:pid`）、内核驱动路径（`/sys/bus/pci/devices/<slot>/driver`）、
  候选模块（来自 `modules.alias` 反查）、该设备固件清单（文件 · 是否存在 · 属哪个包）、`dmesg` 中该设备相关行（最多 20 行，等宽 `.mono-block`，可复制）。
- 交互：`[详情]` ↔ `[收起]`；同一时刻只展开一行。

**F-05 固件缺失清单**
- 元素：`固件缺失 (n)` 小表：`文件` `证据` `建议包` `状态`；`状态` = `未装包` / `已装包但文件缺失`（后者更可疑，值得区分）。
- 无缺失时**整段不显示**（不写「无缺失」这种提示）。
- 每行 `[装此包]` → 跳 F-21 预检（预填 `kind=firmware, name=<包>`）。

**F-06 问题清单 + 处理跳转**
- 列：`级别`（info/warn/error 用 `--text-muted`/`--text`/`--danger` 文字色区分）、`内容`、`处置`、`[处理]`。
- `[处理]` 行为：滚到对应区块 + 预填参数（例：`未安装 dkms` → 安装驱动段预选 `dkms`；`设备 0000:03:00.0 无绑定驱动` → 内核模块段预填候选模块并给出 `[加载]`）。
- 无 issue 时不显示该小段。

**F-07 待生效改动**（`overview.pending`）
- 元素：摘要行下一行 `⚠ 待重启生效: n 项 (查看)`；展开列出：`改动内容` `生效条件`（重启 / 卸载模块后 / initramfs 重建后）。
- 例：`已把 r8169 加入黑名单` → `生效条件: 重启`；`已设置 i915.enable_psr=0` → `生效条件: 卸载并重新加载 i915 或重启`。
- 只显示事实与条件，不写"请重启"。

**F-08 环境/权限异常行**（顶栏）
- 三种情况各显示一行（只在其出现时）：
  1. 后端非 root：`后端权限不足（root 必需），改系统动作已禁用` → 所有 `.btn-danger`/致变按钮 `disabled`。
  2. 非 Debian 系或无 `apt-get`：`当前系统不支持包管理动作`（体检/模块仍可用）。
  3. 工具缺失：`缺少 modinfo`、`缺少 update-initramfs`（逐项列出），相关功能按钮禁用而不是点了报错。

### 3.2 内核模块

**F-10 模块表 + 搜索**
- 元素：`[搜索模块]`（`.input`，300ms 防抖，走接口 `q`）、`已加载 n`、`.table`：`模块` `大小` `被引用` `自启` `黑名单` `描述` `[详情]` `[卸载]` `[自启]` `[黑名单]`。
- 默认按大小降序（内存占用直观）；被引用的模块名可点，跳到引用者。
- `自启`：`自启` / `不自启` / `未知`（未知出现在既无 `modules-load.d` 记录又非设备绑定加载时）；`黑名单`：`已黑名单` / `—`。
- 搜索无结果 → 表格区一行「没有匹配的模块」（数据状态，无操作指引）。

**F-11 模块详情**
- 内容：文件路径、版本、描述、依赖（`depends`）、别名（前 10 条）、参数（名称 · 类型 · 说明 · 当前值）、签名（`sig_id`/`signer`，无签名显示 `—`）。
- 附带：该模块当前是否被设备占用（若 `overview` 里某设备的 `driver` == 本模块，标一行 `占用设备: 0000:00:02.0`）。
- `[复制 modinfo]` 复制详情纯文本。

**F-12 设备→候选模块（别名反查）**
- 元素：`[设备→候选模块]` 按钮 + 输入框（可填设备地址如 `0000:03:00.0`，或直接填 ID `10ec:8168`）。
- 输出：候选模块列表（`模块` · 命中别名 pattern · 是否已加载 · `[加载]`）。
- 用途：插了新网卡/新设备、系统没自动绑定时的第一入口。
- 无候选 → 「没有匹配的模块别名」（数据状态）。

**F-13 加载模块**：`[加载]` → 直接执行（safe），结果行内显示 `已加载 <模块>` 或错误摘要 + `[复制命令]`。执行后刷新模块表与体检（因为设备绑定可能变化）。

**F-14 卸载模块（影响面 + 确认）**
- 点击 `[卸载]` 先在行内展开影响面：`被引用: r8168 (1)` `占用设备: 0000:03:00.0 网络`，
  以及一句后果（由后端 `effect` 拼出，措辞固定）：
  - 显示：`卸载 i915：显示输出正在使用它，执行后会立即黑屏（本机可能只能靠远程恢复）`
  - 网络：`卸载 r8169：当前网络连接正在使用它，执行后会断网（本机可能只能靠物理操作恢复）`
  - 被引用：`卸载 <m>：<n> 个模块正在使用它，将一并卸载`
- 确认要求（两档）：普通卸载 → 点「确认卸载」；**在用/被引用** → 必须输入模块名（`输入模块名以确认: i915`）+ 勾选后果项。
- 后端拒绝（10001）时原样显示后端 message（含 missing 项），不前端伪造。

**F-15 开机自启开关**：`[自启开]`/`[自启关]` → 写托管文件 `/etc/modules-load.d/rc-drivers.conf`；执行后该模块 `自启` 列即时更新，并写入一条 pending（重启后生效）。

**F-16 黑名单开关**：`[加入黑名单]`/`[移出黑名单]` → 写 `/etc/modprobe.d/rc-drivers.conf` + `depmod -a`；
- 加入黑名单时若模块**当前已加载**：行内显示 `已加入黑名单，当前仍加载（重启后不再加载）`，并写入 pending；
- 需要输入模块名确认（warn 级）。

**F-17 模块参数（options）**
- `[参数]` 展开：列出当前托管文件里的 `options <m> k=v` 行 + `[添加参数]`（名称 · 值两个输入，值正则校验）+ 每行 `[删除]`。
- 值非法（含空格/引号/分号等）→ 行内报错「参数值包含非法字符」，不发请求。

**F-18 设计约束**：本页**不提供**"一键卸载在用显示/网络驱动并自动重启"的路径；F-14 的确认只解除拒绝，不做任何自动重启或自动恢复动作。

### 3.3 安装驱动

**F-20 候选包表 + 分类筛选**
- 顶部筛选：`[全部] [固件] [DKMS] [厂商] [工具]`（当前选中用 `.tag-chip` 高亮）。
- 列：`包名` `说明` `已装` `候选` `大小` `建议` `[预检]`。
- `已装`/`候选`：版本号或 `—`；`已装 == 候选` 的行 `[预检]` 禁用并显示 `已是最新`。
- `建议`列显示推导理由：`本机 0000:03:00.0 缺失 rtl_nic/rtl8168g-2.fw` / `本机未装 dkms` / `本机有 NVIDIA 设备`。
- 空筛选结果 → 一行「没有匹配的包」（数据状态）。

**F-21 预检计划面板**（无副作用，纯计算）
- 展开位置：该行下方（`.section` 内嵌）。
- 内容（全部来自后端 `plan`）：
  1. `将安装: firmware-iwlwifi 20230210-5 (3120 KB)`；`将替换: <pkg> a→b`；`将跳过: <pkg> 已是最新`。
  2. `将执行的命令`：逐行等宽显示（这是核心透明度），每行右侧 `[复制]`。
  3. `影响`：`网络 无` `显示 无` `存储 无` `initramfs 会重建` `DKMS 会编译模块` `需重启`。
  4. `风险`：逐条（例：`将新装 1 个包`、`该动作会重建 initramfs`、`Secure Boot 已开启，DKMS 模块需要 MOK 签名后才能加载`）。
  5. `执行前会先备份`（含备份落点路径，可复制）。
  6. `[确认执行]`（`.btn-danger`）+ `[取消]`。
- 计划有效期：面板顶部显示剩余有效时间（120s 倒计时）；过期后 `[确认执行]` 变 `[重新预检]`。

**F-22 确认执行**
- 交互：需要 ① 勾选 `requires_confirm` 列出的每一项（文案由后端给，如「我了解将执行上述 apt 命令」）；② 输入包名（`输入包名以确认: firmware-iwlwifi`）。两者齐了 `[确认执行]` 才可点。
- 提交后：立即返回 `task_id` → 面板切换为 F-23；体检/摘要进入"有任务"状态。
- 若返回 10004（状态已变）：面板显示「系统状态已改变（已装包/候选版本有变化），需重新预检」并只留 `[重新预检]`。
- 若返回 10001：缺失项原样列出。

**F-23 任务进度**
- 顶部活动任务条（全局共用一个）：`<动作>` `<状态>` `<百分比>` 当前命令；`[详情]` `[取消任务]`。
- 展开详情：命令流（每行 `命令` + `rc` + `耗时`，运行中 rc 为空）、`.progress` 进度条、`输出尾部`（等宽，最多 4KB，自动滚到底部、可手动停止跟随）。
- 轮询：仅在有活动任务时 2s 轮询 `drivers.task`；结束时停轮询。
- 进度百分比来自后端 `progress.pct`（apt 阶段按命令数近似，不假装精确）。

**F-24 任务结束摘要 / 失败处置**
- 成功：`已完成: 安装 firmware-iwlwifi (24.3s)` + `已装: firmware-iwlwifi 20230210-5` + 若 `effects.reboot_required` 则一行 `需重启后生效` + 相关后续动作入口（例：装完 dkms 后 `[继续装 linux-headers]`）。
- 失败：错误摘要（rc + 后端 message）+ 输出尾部 + `[复制命令]` + `[查看日志]` + `[重试]`（重新预检再走一遍）+ `[恢复备份]`（跳 F-32）。
- 面板**不自动消失**，保留到你切换区块或手动关闭。

**F-25 取消任务**
- 仅在任务未进入 apt/dkms/initramfs 阶段可取消（后端 10009 兜底）；可取消时按钮可用，否则禁用并在按钮 title/行内说明不可取消的阶段（不是提示语，是状态原因）。

**F-26 DKMS 一键准备**
- 触发：体检 issue `未安装 dkms` 的 `[处理]`，或 DKMS 分类下 `[准备 DKMS 环境]`。
- 行为：生成**一个组合计划**（`dkms` + `linux-headers-<kver>` + `build-essential`），走 F-21/F-22 同一套流程。
- 完成后把 `tools.dkms`/`tools.headers` 置为已装（重新体检确认），并提示 DKMS 分类下可选驱动。

**F-27 固件推荐置顶**
- 规则：`overview.firmware.missing` 反推出的包，在固件分类里置顶并标 `建议`，理由写明「本机缺失 <固件文件>」。

**F-28 厂商驱动分区**
- 仅当设备表里识别到 NVIDIA / AMD 独显 / Broadcom 无线时，`厂商` 分类才出现对应候选（`nvidia-driver` / `nvidia-kernel-dkms` / `broadcom-sta-dkms` / `firmware-amd-graphics` …）。
- 分区顶部一行事实：`检测到 NVIDIA 设备 0000:01:00.0 (未绑定驱动)`。
- Secure Boot 开启时：该分区显示一行 `Secure Boot 已开启，DKMS 模块需 MOK 签名后才能在启动时加载`，并把「签名步骤」以只读命令形式列出（`[复制]`），**不代做**。

**F-29 apt 组件缺失**
- 若缺 `non-free-firmware`：在固件分类顶部显示一行 `apt 源缺少 non-free-firmware 组件，固件包不可安装` +
  `[复制命令]`（给出你自己加源的命令文本），**扩展不改源、不加仓库**。

### 3.4 备份与日志

**F-30 备份列表**
- 列：`时间` `触发`（哪个接口/动作）`大小` `条目` `校验`（sha256 前 12 位，可复制）`[恢复]` `[删除]`。
- 排序：新→旧；默认显示最近 10 条，`[显示全部]` 展开。
- 点击时间列显示落点路径（`<扩展目录>/.data/driver-backup-*.tar.gz`），可复制。

**F-31 立即备份**
- `[立即备份]` → 调 `drivers.rollback{mode:"create", note:"手动"}`；完成后列表新增一行，并把备份 id 显示为可复制文本。
- 手动备份与动作前自动备份在 `触发` 列区分（`手动` / `安装 firmware-iwlwifi` / `卸载 r8169` …）。

**F-32 恢复（预检 → 确认 → 任务）**
- `[恢复]` → 预检面板：`将还原: /etc/modprobe.d/intel-microcode-blacklist.conf`、
  `将新建: /etc/modprobe.d/rc-drivers.conf`、`将删除: /etc/modules-load.d/rc-drivers.conf`（若备份里没有它），
  `影响: initramfs 会重建`、`需重启`；`[确认恢复]` 需勾选 + 输入备份时间戳确认。
- 执行走任务（F-23）；完成后刷新体检/模块表，并写入一条 pending（重启生效）。

**F-33 删除备份**：`[删除]` → 行内二次确认（`[确认删除]`/`[取消]`），删除后不可恢复。

**F-34 日志表**
- 列：`时间` `动作` `结果`（`成功`/`失败`）`耗时` `命令数` `[详情]`。
- 默认 50 条，`[加载更多]` 翻页；`结果=失败` 行用 `--danger` 文字色。
- 空 → 一行「暂无记录」。

**F-35 日志详情**：展开显示该次动作的全部命令（命令 · rc · 耗时 · 输出尾部），每条命令可 `[复制]`；顶部显示触发接口、备份 id（若产生）。

**F-36 复制日志**：`[复制日志]` 把当前可见日志拼成纯文本（含命令与输出尾部）写剪贴板。

**F-37 任务历史**：任务条 `[详情]` → 面板里分两组：`进行中`（最多 1 条）与 `最近任务`（最多 50 条：时间 · 动作 · 结果 · 耗时），点某条看它的命令流。

### 3.5 全局

**F-40 后端状态 + 重启后端**
- 正常时不显示任何东西（后端在线是常态）；异常时摘要行显示一行 `后端已停止` + `[重启后端]`（调面板 `POST /api/ext/backend/restart`）。
- 接口全部失败（`rpc_error 4301` 离线）时：区块显示 `后端离线` + `[重启后端]`，并使用上次成功数据（若内存里有）而不是清空页面。

**F-41 忙碌互斥**：存在活动任务时，所有致变按钮 `disabled`（title/行内给出原因：`有任务正在执行`，属状态原因，不是提示语）；任务条始终可见以便取消/查看。

**F-42 离开页面任务继续**：任务在后端执行；离开再回来用 `drivers.task`（无 id）恢复显示进行中任务与历史。

## 四、状态与数据流

| 时机 | 动作 |
|---|---|
| 进页面 | 并行取 `overview`(20s) + `packages`(20s) + `modules`(20s) + `rollback{list}` + `log{limit:50}`；取到后渲染 |
| 点刷新 | `overview{refresh:true}` + `packages`（只刷这两项） |
| 有活动任务 | 每 2s `task{id}`；无活动任务不轮询 |
| 任务结束 | 一次性刷新 `overview` + `packages` + `modules` + `log` + `rollback{list}` |
| 模块/黑名单/自启/参数动作后 | 刷新 `modules` + `overview`（设备绑定与 pending 可能变化） |
| 安装/恢复完成后 | 刷新 `overview` + `packages` + `log` + `rollback{list}` |
| 页面卸载 | 停轮询（任务继续） |

错误统一呈现：`.error` 一行 = 后端 `rpc_error.message`（原样）；网络层失败 = `请求失败: <status>`；
可重试的动作在错误行右侧给 `[重试]`。

## 七、明确不做的功能

1. 不自动重启、不自动卸载在用显示/网络驱动、不做"崩溃自动恢复"。
2. 不改/加 apt 源、不开启 apt 组件（只显示手工命令供复制）。
3. 不代做 MOK 签名、不代做内核 cmdline/grub 修改、不装 `.run` 第三方脚本。
4. 不提供"手填任意包名"安装（只走内置白名单目录）。
5. 不做"驱动版本降级"（apt 快照/pinning 不在范围）。
6. 不显示无来源的"驱动评分/兼容性"等杜撰信息。
7. 不在本页重复面板「系统扩展」页的扩展管理功能（更新/卸载扩展本身）。

## 九、待确认（功能取舍）

1. **布局**：默认**单页滚动四段、不用选项卡**（与"移除页内选项卡、去掉页头标题"的既有要求一致）；若你要选项卡也可以，改一行结构。
2. **危险确认强度**：默认"在用/被引用模块卸载"要**输入模块名 + 勾选后果**；安装/恢复要**输入包名/时间戳 + 勾选**。若嫌繁琐可降为只勾选。
3. **体检报告复制**：默认提供（纯前端拼文本）；如不需要可去掉。
4. **F-31 手动备份**、**F-33 删除备份**、**F-37 任务历史**：默认提供；如要精简可去掉这三个。
5. **分区顺序**：默认 体检 → 内核模块 → 安装驱动 → 备份与日志（按"看 → 查 → 改 → 兜底"排列）。
