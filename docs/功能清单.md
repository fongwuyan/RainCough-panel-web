# RainCough 功能清单

> ⚠ 本文是 **v4 重构前基线**（2026-10-17 之前）。v5 已定：只保留 工作台/文件管理/终端/插件/设置/常驻浮窗，
> 其余系统功能与 17 个业务插件全部移除。技术栈最终定为 **Vue3 + Go 标准库（零第三方依赖、零外部命令）**。
> 现行方案见 `重构方案-v6.md`。

> 用途：重构前的功能基线。以代码实测为准（2026-10-17），不以 reader.txt 的历史叙述为准。
> 规模：Go 17,040 行 / 122 条 `/api` 路由 / 254 个接口 / 76 个 Vue 组件。

## 1. 定位

自托管 Linux 运维面板。一个 Go 二进制监听 :3900，同时提供 HTTP API 与 Vue3 单页前端；功能通过三种形态承载，互不重叠：

| 形态 | 实现 | 数量 | 入口 |
|---|---|---|---|
| 内置功能 | Go（`cmd/raincough`） | 7 项 | 侧边栏固定项 |
| 插件 | Python + systemd + UDS RPC | 17 个 / 184 接口 | `/plugin/<name>` |
| 系统扩展 | extension.json + 前端产物 + 可选 Python 后端 | 1 个 / 4 接口 | `/ext/<name>` |

## 2. 内置 7 项（用户可见入口）

**工作台 `/`** — 概览（主机名/运行时长/启动时刻）、服务器信息（系统·架构/CPU 型号/内存/Go 版本/进程线程/交换）、CPU 核心网格、内存、磁盘总览、网络（主图 + 分接口累计）、Load Average、GPU、磁盘设备表、性能趋势图；常驻历史由服务端每秒采样（`/api/workspace/history`，唯一清理入口是存储清理）。

**文件管理 `/fm`** — 目录浏览与跳转、收藏、分片上传（8MB/片、冲突策略 rename/overwrite）、下载（直连/打包）、新建目录、重命名、删除、哈希、解压（含密码）、文本读写（仅 UTF-8，其它编码显式拒绝）、体积统计、异步批量操作（复制/移动/压缩，可取消/下载）、预览、搜索（文件名/类型/大小/修改天数）。

**终端 `/terminal`** — 多 PTY 会话（open/input/resize/close/stream）、主机管理（增删改排序）、快捷命令库（增删改）。

**系统扩展 `/ext`** — 已装扩展列表、安装/更新/卸载、自带后端进程状态与重启；扩展前端产物由 `/api/ext/<name>/assets/extension.js` 托管。

**插件 `/plugins`** — 已装列表、插件市场（registry/ping/install/update/remove）、仓级更新日志、单插件设置、统一任务队列浮层。

**设置 `/settings`** — 外观（深/浅色）、仓库配置（插件市场与面板仓库地址）。

**开发文档 `/docs`** — 插件开发指南、v4 迁移、接口库设计等。

**常驻浮窗** — 面板更新（检查 → 下载应用 → 确认重启 → 回滚），挂在侧边栏标题右侧。

## 5. 系统扩展

机制：`extension.json`（name/label/route/backend/interfaces）+ `assets/extension.js`（注册 `window.__rcExt__`，宿主 Vue 运行时挂载）+ 可选 `server.py`（systemd 单元 `rc-ext-<name>.service`）。扩展可声明接口供他人 `ctx.invoke`。

现存唯一扩展 **drivers**（硬件与矿卡驱动）：`drivers.gpu`（型号/架构/算力/GSP/是否矿卡/容器直通）、`drivers.repo`（清单来源：直连→gh-proxy→本地，GPG 验签）、`drivers.repo.config`（分支/镜像/令牌只写不读/指纹 pin）、`drivers.install`（两阶段：precheck 出计划 → apply 起异步任务；kind=mod/container-toolkit）。目标卡：P104-100 / P106-100 / CMP 30HX。

## 6. ⚠ 后端仍在、前端已无入口（孤儿功能）

2026-10-02 按需求删除 media / tasks / scheduler / syscenter 四个扩展包，但后端与路由未清理：

- **39 条 `/api/sysfunc/*` 路由仍在**（main.go 22 + syscenter_ext 9 + syscenter 3 + backup 3 + apimon 2），前端包已删 → 日志、进程、服务、用户、SSH 密钥、内核、清理、开关机计划、时间同步、logrotate、备份任务、API 监控、启动历史全部**不可达**。
- `router.js` 仍把 `/media` `/tasks` `/scheduler` `/sysfunc` 重定向到 `/ext/*`，目标扩展不存在 → 旧书签落到「扩展未就绪」。
- `api.js` 中 `schedJobs` `mediaList` `sysLogs` `sysProcesses` `envCatalog` `bkpList` 等**只被 api.js 自己引用**，无任何组件调用。

重构含义：这批功能要先定性 —— 复活（补 UI）、下线（删后端）、还是降级为纯接口（只留 `system.*` 供插件调用）。定性之前不要动 `internal/core` 里对应的实现。

## 7. 数据与状态

- 单 sqlite `data/rc.db`，`ns_<ns>_kv` 按命名空间分表；`core_registry` 持久化接口注册表。
- 插件产物目录 `cache/ output/ work/`，由主系统代发。
- 前端状态：`stores/{plugins,extensions,ui,jmcomic}`；收藏与主题落 localStorage。

## 8. 重构前必须知道的三条事实

1. **功能归属是三层混的**：同样是"系统信息"，`/api/system` 是内置页面直连，`system.info` 是接口库视图，两者代码路径不同但语义重叠。合并前先定唯一真源。
2. **契约没有守卫**：前端 149 个 api 方法 ↔ 后端 122 条路由，无自动对拍；历史上"空壳/死按钮"全部出在这里（`panelVersion` 整组、`pluginSettingsGet`、`bkpList`、`fmSearch`）。
3. **全站无鉴权**：`StatusUnauthorized` 零命中，`/api/store/settings` 可改 `plugin_repo` → 装插件即执行 pip → 局域网 RCE 面。
