# 系统扩展「驱动」设计方案（v3 · 实施设计）

> v1 的错误：把驱动逻辑写在面板 Go 里，等于每加一个扩展都要改面板二进制。
> v2 改成：**扩展包自带后端与接口**，安装即注册接口，卸载即注销；面板二进制只提供机制。
> v3（本文）：机制已经落地并在真机验证过，这里把「驱动」扩展设计到**照着写代码**的精度 ——
> 包结构、清单全文、9 个接口的入参/出参/命令模板/解析来源、后端与前端实现设计、护栏规则表、分阶段验收。
> 本文只写设计，代码未动。

版本口径：面板 `VERSION` 冻结在 `1.0.0`，扩展自身 `version` 也写 `1.0.0`；**不说变就不变**。

## 一、机制契约（写扩展必须遵守，全部已在代码中生效）

### 1.1 包结构与清单

```
extensions/<name>/
  extension.json          清单（name 必须 == 目录名）
  frontend/extension.js   前端入口（唯一约定入口名，可 import .vue）
  frontend/*.vue          组件源码
  assets/extension.js     构建产物（随库提交，面板经 /api/ext/<name>/assets/ 托管）
  server.py               后端（可选：清单声明 backend.exec 才有）
```

`extensions/registry.json` 是可安装清单（面板「系统扩展」页读它；拉不到时回退本地目录扫描）：

```json
{ "extensions": [ { "name": "...", "label": "...", "version": "1.0.0", "description": "...",
                    "author": "...", "icon": "AB", "route": "/ext/...",
                    "backend": { "lang": "python", "exec": ["python3", "server.py"] },
                    "interfaces": [ ... ] } ] }
```

构建：`node tools/build-extension.js <name>`（校验 name==目录名；`vue`/`vue-router`/`rc-api` 映射到宿主运行时）。

### 1.2 端点与线协议

- 面板启动/重扫时为**声明了 backend.exec 的每个扩展**预建端点，写 `<扩展目录>/.rc.endpoint`：
  `unix:/run/raincough/plugins/<name>.sock`（Linux）或 `tcp:127.0.0.1:<port>`（Windows 开发降级）。
- 传输：**换行分隔的 JSON-RPC 2.0**，单帧上限 8MB。
- 后端 → 面板（请求，面板回 `{jsonrpc,id,result|error}`）：

| method | params | 说明 |
|---|---|---|
| `register` | `{name, version, iface_ids[], heartbeat_sec, protocol_version:1, token?}` | `name` 必须等于端点名；`protocol_version` 只能 1 或省略；面板已配 token 时必填 |
| `heartbeat` | `{version?}` | 未注册就心跳 → 错误；面板探针 10s 周期，超时标 offline |
| `unregister` | — | 主动注销 |
| `call` | `{iface, params, timeout_ms?}` | 跨插件调用（走同一路由与权限判定） |

- 面板 → 后端：`{"jsonrpc":"2.0","id":N,"method":"invoke","params":{"iface":"<id>","params":{...}}}`，
  后端回 `{"jsonrpc":"2.0","id":N,"result":{...}}` 或 `{"jsonrpc":"2.0","id":N,"error":{"code":...,"message":"..."}}`。
- 面板侧 HTTP：`POST /api/interfaces/<id>/invoke` body `{params, timeout_ms}` →
  `{"ok":true,"result":...}` / `{"ok":false,"rpc_error":{"code","message"}}`。
  **默认超时 15s**（`timeout_ms<=0` 时）→ 任何可能超过 15s 的动作都必须显式传 `timeout_ms` 或走异步任务。

### 1.3 生命周期

1. 安装扩展：下载解包 → 校验 → 写目录 → **先重扫建端点并写 `.rc.endpoint`** → 再生成并 `enable --now` 单元
   `rc-ext-<name>.service`（`User=root`、`WorkingDirectory=<扩展目录>`、`ExecStart=<清单 exec>`、
   `Environment=RC_EXT_NAME/RC_EXT_DIR`、`Restart=always` `RestartSec=5`）。
2. 卸载：**停单元（disable --now）→ 删目录 → 摘接口注册**（顺序不能换；先删目录会留下半死进程/占用目录）。
3. 面板重启不影响后端进程；但面板会重建 socket，后端的连接会断 → **后端必须自愈重连并重新 register**。
4. 运行期接口：`GET /api/ext/backend[?name=]`（`active`/`unit`/`exec`/`interfaces`）、
   `POST /api/ext/backend/restart {name}`。
5. `GET /api/interfaces` 列接口（id/visibility/version/online/calls/avg_ms/p95_ms/last_error/provider）。

### 1.4 前端合约

- 路由 `/ext/<name>`；加载器 `ExtView.vue` 取产物 → `eval` → 取注册并挂载。
- 产物必须注册：`window.__rcExt__[<name>] = { mount(el, ctx) { ...; return () => unmount() } }`。
- `ctx = { navigate(to), host }`；`host = { Vue, api, req(method, path, body), navigate, router(), hostVersion, usePreview }`。
- 扩展内调自己的接口：`host.api.ifaceInvoke(id, params, timeoutMs)`（等价于 POST `/api/interfaces/<id>/invoke`）。
- 产物不打包 Vue/api（几十 KB 级）；样式由 SFC 编译后注入 `<style>`。
- 界面规矩（沿用面板既有要求）：直角（radius 0）、文字按钮、不用 emoji、页面内不写静态提示语、不写页头标题。

### 1.5 权限（`invokeFrom` 实测语义）

| visibility | 谁能调 |
|---|---|
| `private` | 只有提供者自己 |
| `main` | 只有面板界面（caller=`ui`）与提供者自己 → **插件调不到** |
| `all`（默认） | 任意已注册插件 + 面板界面 |

→ 驱动扩展里凡是**会改系统状态**的接口一律 `main`：插件即使装上也没有装驱动/卸载模块的能力。

### 1.6 三个实测坑（写后端时要绕开）

1. 「端点还没建好」：安装流程刚触发时 `.rc.endpoint` 可能不存在 → 连接要重试（样板实现：20 次 × 1.5s）。
2. `register.name` 必须 == 端点名 == 目录名；清单 name 与目录名不一致的包在安装时会被面板拒绝。
3. 面板重启后连接断开 → 外层循环退避重连（1/2/5/10/30s），期间长任务线程不受影响。

## 三、接口详细设计

错误码约定（面板只透传 `rpc_error.code/message`；框架码：`-32601` 未知方法、`-32602` 参数错、`4001` 接口未注册、`4201` 权限、`4301` 离线）：

| 码 | 含义 |
|---|---|
| 10001 | 需要确认（缺 `confirm` 或确认项不全） |
| 10002 | 参数非法（名字不合法/未知 kind） |
| 10003 | 计划不存在或已过期（默认 120s） |
| 10004 | 状态已变（预检后系统状态变了，必须重新预检） |
| 10005 | 环境不支持（非 Debian 系/工具缺失） |
| 10006 | 任务不存在 |
| 10007 | 忙碌（同刻只允许 1 个改系统任务） |
| 10008 | 路径/内容被白名单拒绝（备份解包等） |
| 10009 | 不可取消（已进入 apt/dkms/initramfs 阶段） |

**数据来源（实现按此写，不猜）：**

| 字段 | 来源 |
|---|---|
| 系统/内核/架构 | `/etc/os-release`、`os.uname()`（等价 `uname -r/-m`） |
| Secure Boot | `/sys/firmware/efi/efivars/SecureBoot-*` 第 5 字节（`0x01` 开）；有 `mokutil` 则 `--sb-state` 复核；**只读不改** |
| 虚拟化 | `/sys/class/dmi/id/product_name` + `/proc/cpuinfo` hypervisor 标志（kvm/qemu/none） |
| apt 组件 | 解析 `/etc/apt/sources.list` 与 `/etc/apt/sources.list.d/*.list|*.sources`（只读，绝不改写） |
| 设备表 | `/sys/bus/pci/devices/*/{vendor,device,class,uevent}` + `/sys/bus/usb/devices/*/uevent`；`DRIVER=` 行或 `<dev>/driver` 符号链接判绑定 |
| 设备名称 | `lspci -nnmm`（存在时）；否则解析 `/usr/share/misc/pci.ids`；都没有就只显示 ID |
| 模块文件/版本 | `/usr/sbin/modinfo -F filename -F version <mod>`；工具缺失时查 `/lib/modules/<kver>/modules.dep` |
| 设备类别归类 | class 前两位：`03`=display、`02`=network、`01`=storage、`0c03`=usb、`04`=audio（用于影响评估） |
| 固件缺失 | `dmesg` 中 `Direct firmware load for X failed` / `firmware: failed to load X` → `/lib/firmware/X` 不存在 |
| 固件→包 | 内置前缀表（`iwlwifi-*`→firmware-iwlwifi、`rtl_nic/*`→firmware-realtek、`rtw88/*`→firmware-realtek、`brcm/*`→firmware-brcm80211、`ath10k/*`→firmware-atheros、`amdgpu/*`→firmware-amd-graphics、`nvidia/*`→firmware-nvidia-graphics、其余→firmware-misc-nonfree）；已装的用 `dpkg -S /lib/firmware/X` 反查更准 |
| headers | `/lib/modules/<kver>/build` 存在 或 `dpkg-query -W linux-headers-<kver>` |
| build-essential | `dpkg-query -W build-essential gcc` |

**issues 规则表：**

| 判定 | severity | fix |
|---|---|---|
| 未装 dkms | info | 装 `dkms` |
| 未装 headers | info | 装 `linux-headers-<kver>` |
| dmesg 有固件失败行 | warn | 装对应 firmware 包 |
| 设备无绑定驱动，但 `modules.alias` 有候选 | warn | `drivers.module.action{load, module}` |
| Secure Boot 开启且设备需要 DKMS/第三方模块 | warn | 只提示（要 MOK 签名，本扩展不代做） |
| 缺 `non-free-firmware` 组件 | warn | 只提示（不改源） |
| 已加载模块无对应设备且无人使用 | info | 建议卸载（不自动） |

### 3.2 `drivers.modules`（all，只读）

`params`: `{q?, limit?}`；`q` 命中名称/描述/别名模式。

`result`: `{ total, items:[ { name, size_b, used_by:[...], refcount, module_file, version, description,
autoload:{state:"yes|no|unknown", sources:["/etc/modules-load.d/modules.conf"]},
blacklisted:{state, source}, params:{...} } ], aliases:[{pattern,module}] }`

来源：`lsmod`（或 `/proc/modules`）、`modinfo -F description -F filename -F version -F parm`、
`/lib/modules/<kver>/modules.alias`、`/etc/modprobe.d/*.conf`（blacklist/options）、
`/etc/modules-load.d/*.conf` + `/etc/modules`（持久化），以及本扩展的托管文件 `rc-drivers.conf`。

### 3.3 `drivers.module.action`（main）

`params`: `{action, module, confirm?, params?}`

| action | 命令模板 | 分级 | 条件 |
|---|---|---|---|
| `load` | `/usr/sbin/modprobe <m>` | safe | — |
| `unload` | `/usr/sbin/modprobe -r <m>` | danger | 被引用（used_by 非空）或属在用 display/network → 必须 `confirm.typed == module`；在用显示/网络还需 `confirm.acknowledge` 含 `risk-display`/`risk-network` |
| `persist_on` | 写托管文件 `/etc/modules-load.d/rc-drivers.conf` | safe | — |
| `persist_off` | 从托管文件移除该行 | safe | — |
| `blacklist` | 写 `/etc/modprobe.d/rc-drivers.conf` 的 `blacklist <m>` + `depmod -a` | warn | 需要 `confirm.typed == module` |
| `unblacklist` | 从托管文件移除 | safe | — |
| `params_set` / `params_del` | 托管文件 `options <m> k=v ...` | warn | 值校验 `^[A-Za-z0-9_.,:=+-]{0,200}$` |

- 模块名正则：`^[A-Za-z0-9_][A-Za-z0-9_-]{0,63}$`（否则 10002）。
- **绝不改他人文件**：只写 `rc-drivers.conf` 两个文件（`/etc/modprobe.d/` 与 `/etc/modules-load.d/` 各一个），
  其它 `*.conf` 只读解析。这也是回滚能精确到"只删自己那几行"的前提。
- 改动前自动备份（见 3.6），备份失败则拒绝执行。
- `result`: `{ ok, module, action, commands:[{cmd,rc,ms,out_tail}], backup:"<id>", effect:{network,display,storage,reboot_required} }`

### 3.4 `drivers.packages`（all，只读）

`params`: `{kind?: "firmware|dkms|vendor|headers", q?}`

`result`: `{ catalog:[ { kind, name, summary, installed:"20230210-5"|null, candidate:"20230210-5"|null,
component:"non-free-firmware", size_kb, installed_size_b, recommended_for:["0000:03:00.0"], reason } ],
apt: { components:{...}, cache_seen:true } }`

- 候选来自**内置白名单表**（server.py 内写死，不接受任意包名）：
  `firmware-{linux-free,misc-nonfree,realtek,iwlwifi,atheros,brcm80211,ti,mediatek,amd-graphics,nvidia-graphics}`、
  `dkms`、`linux-headers-<kver>`、`build-essential`、`broadcom-sta-dkms`、`rtl8821ce-dkms`、
  `nvidia-kernel-dkms`、`nvidia-driver`。
- 状态解析：`apt-cache policy <pkg>`（Installed/Candidate）+ `dpkg-query -W -f=${Status} ${Version} <pkg>`。
- `recommended_for` / `reason` 由 overview 的设备与固件缺失推导（例：`rtl_nic/*` 缺失 → 推荐 firmware-realtek）。

### 3.5 `drivers.install`（main，两阶段）

**阶段 1 `{mode:"precheck", kind, name}`** → 计划（**不发任何命令**，纯计算）：

```json
{ "plan_id": "p-7f3a91", "created_at": 1759450000, "expires_at": 1759450120,
  "kind": "firmware", "name": "firmware-iwlwifi",
  "need_apt_update": true,
  "packages": [ { "name": "firmware-iwlwifi", "current": null, "candidate": "20230210-5",
                  "action": "install", "size_kb": 3120, "essential": false } ],
  "commands": [ { "cmd": "/usr/bin/apt-get update", "why": "候选版本核对" },
                { "cmd": "/usr/bin/apt-get install -y --no-install-recommends firmware-iwlwifi", "why": "安装固件包" } ],
  "effects": { "network": false, "display": false, "storage": false, "initramfs": false,
               "dkms_build": false, "reboot_required": false, "size_kb": 3120 },
  "risks": [ { "id": "apt-new-packages", "severity": "info", "text": "将新装 1 个包" } ],
  "requires_confirm": ["apt-install"],
  "backup_required": true,
  "state_hash": "sha1:..." }
```

**阶段 2 `{mode:"apply", plan_id, confirm:{typed:"firmware-iwlwifi", acknowledge:["apt-install"]}}`** → `{task_id}`

- 校验：计划存在且未过期（10003）、`state_hash` 未变（10004）、`confirm.typed == name` 且 `acknowledge` 覆盖
  `requires_confirm`（10001）。
- 执行序列（任务线程）：备份 → `apt-get update`（若 need）→ `apt-get install -y --no-install-recommends <pkgs>`
  （`DEBIAN_FRONTEND=noninteractive`，超时 1800s）→ 若含 dkms → `dkms status` 复核 → 若 `effects.initramfs` →
  `update-initramfs -u -k all` → `dmesg | tail -50` 采集 → 写日志。
- 失败：**不回滚包**（apt 自身事务），返回 `apt-get remove <pkgs>` 的处置命令 + 输出尾部 4KB，任务标 failed。
- 明令禁止：`upgrade`/`dist-upgrade`/`autoremove`、装 recommends、加/改 apt 源或第三方仓库、跑 `.run` 脚本（P4 另议）。
- `kind=vendor` 只在内核识别到对应厂商设备时才在候选里出现（NVIDIA/AMD/Broadcom）。

### 3.6 `drivers.rollback`（main）

- `{mode:"list"}` → `{backups:[{id,created_at,trigger,size_b,sha256,entries:{modprobe_d,modules_load_d,modules},note}]}`
- `{mode:"precheck", id}` → `{plan_id, files:[{path,action:"restore|create|delete"}],
  effects:{initramfs:true,reboot_required:true}, requires_confirm:["restore-modules"]}`
- `{mode:"apply", plan_id, confirm}` → `{task_id}`：解包白名单路径 → `depmod -a` →（有变化时）`update-initramfs -u -k all`

备份内容与位置：

- 目标：`<扩展目录>/.data/driver-backup-<YYYYMMDD-HHMMSS>.tar.gz`
- 内容：`etc/modprobe.d/`、`etc/modules-load.d/`、`etc/modules`，外加旁挂 `manifest.json`
  （`created_at` / `trigger`（哪个接口/动作）/ `commands` / `sha256` / `uname -r` / `lsmod` 摘要 / `dkms status` 摘要）。
- 解包安全：只接受成员以这三个路径开头，禁止绝对路径、`..`、符号链接（`tarfile` 过滤）；违反 → 10008。
- 保留最近 20 个，超出删最旧。**不随扩展卸载被删除**（卸载扩展不删 `.data`，并在卸载前提示路径）——
  备份的意义就是出问题时还在。

### 3.7 `drivers.task`（all）/ `drivers.cancel`（main）

`drivers.task {id}` →

- 并发：**全局同时只允许 1 个改系统任务**（apt/dkms/initramfs 不可并发），否则 10007。
- 任务表：内存 + 落盘 `<扩展目录>/.data/driver-tasks.ndjson`（保留最近 50 条；后端/面板重启后仍在跑的任务标 `interrupted`）。
- 取消：仅 `queued` 或尚未进入 apt/dkms/initramfs 的任务可取消（10009 否则）——避免留下 dpkg 锁。

### 3.8 `drivers.log`（all）

`{limit?, q?}` → `{ total, file:"<扩展目录>/.data/driver-log.ndjson",
items:[{ ts, actor:"ui", iface, action, params, result:"ok|fail", commands:[{cmd,rc,ms,out_tail}], backup, note }] }`

- 每条动作一行 NDJSON；命令、输出尾部（各截 4KB）、退出码、耗时、时间、触发接口全留痕。
- 超过 2MB 时截断保留末 1000 行。

## 四、后端 `server.py` 实现设计

- **只用标准库**（`json os socket subprocess shutil tarfile hashlib re time threading queue datetime`），与插件环境一致，零第三方依赖。
- 分层（单文件内分段，目标 ≤900 行）：`rpc`（连接/注册/心跳/重连/分发）→ `probe`（overview/modules/packages 采集）→
  `kmod`（模块动作）→ `apt`（预检/安装）→ `backup`（打包/恢复）→ `tasks`（单工作线程队列 + 进度）→ `audit`（日志）。
- **工具解析必须用绝对路径候选表**，不能依赖 PATH：

```python
TOOLS = {
  "modprobe":  ["/usr/sbin/modprobe", "/sbin/modprobe", "/bin/kmod"],
  "modinfo":   ["/usr/sbin/modinfo", "/sbin/modinfo", "/bin/kmod"],
  "depmod":    ["/usr/sbin/depmod", "/sbin/depmod"],
  "update_initramfs": ["/usr/sbin/update-initramfs", "/usr/sbin/update-initramfs"],
  "apt_get":   ["/usr/bin/apt-get"], "apt_cache": ["/usr/bin/apt-cache"],
  "dpkg_query":["/usr/bin/dpkg-query"], "lspci": ["/usr/bin/lspci"], "lsusb": ["/usr/bin/lsusb"], "ip": ["/usr/bin/ip"],
}
```

  （宿主实测：`/usr/sbin/{modprobe,modinfo,depmod,insmod,rmmod}` 是指向 `/bin/kmod` 的软链；
  以用户 `f` 登录时 `/usr/sbin` 不在 PATH，`command -v modprobe` 为空 → 依赖 PATH 必踩坑。）

- 命令执行器：`subprocess.run(args_list, capture_output=True, text=True, timeout=…)`，**永不 `shell=True`**；
  输出各截 8KB；`rc/timeout` 都记入审计。
- 超时表：`modprobe` 30s、`depmod` 60s、`apt-get install` 1800s、`apt-get update` 300s、
  `update-initramfs` 300s、只读探测 10s。
- 端点自愈：外层 `while True`：`connect()`（20×1.5s 重试）→ `register` → 心跳线程（5s）→ 读循环 →
  断线 → 退避重连 1/2/5/10/30s；任务线程与读循环解耦，重连期间长任务继续跑，重连后重新 `register`。
- 运行环境要求（诊断用）：`/etc/os-release` 含 `debian|ubuntu`，否则 10005 并在 overview 里说明；
  `apt-get` 缺失 → 10005；`dkms` 缺失 → 相关动作直接给"先装 dkms"的 fix，不静默失败。
- 数据落点：`<RC_EXT_DIR>/.data/`（备份、任务、日志），**不写 /etc 之外的地方**；托管文件仅
  `/etc/modprobe.d/rc-drivers.conf`、`/etc/modules-load.d/rc-drivers.conf`。

## 五、前端实现设计

结构：`frontend/extension.js`（入口：`window.__rcExt__.drivers = { mount(el, ctx) }`，内部 `ctx.host.Vue.createApp(App)`）
+ `App.vue`（四段外壳 + 顶栏体检摘要 + 任务条）+ 四个区块组件。

- 状态：`overview`、`modules`、`packages`、`plan`、`task`、`backups`、`log`、`busy`、`err`。
- 取数：全部走 `ctx.host.api.ifaceInvoke(id, params, timeoutMs)`（只读 20000ms；动作 60000ms；apply 立即返回 task_id）。
- 轮询：存在活动任务时 2s 轮询 `drivers.task`；无任务时**不轮询**（不打扰、不耗电）。
- 四个区块（页面内不写页头标题，直接进内容）：

| 区块 | 内容 | 交互 |
|---|---|---|
| 体检 | 摘要行（内核 · 架构 · Secure Boot · DKMS · headers）；设备表（总线/地址/类别/名称/驱动/固件/状态）；问题清单 | 每条问题右侧一个「处理」→ 跳对应区块并预填（如"装 firmware-iwlwifi"） |
| 内核模块 | 搜索 + 列表（名称/大小/被引用/自启/黑名单/描述） | 行内文字按钮：加载 / 卸载 / 自启开 / 自启关 / 加入黑名单 / 移出黑名单；卸载在用模块要**输入模块名**确认 |
| 安装驱动 | 候选表（种类/包名/说明/已装/候选/大小/建议理由） | 选中 →「预检」→ 计划面板（命令清单、将装/替换的包、影响评估、风险）→「确认执行」（勾选同意项 + 输入包名）→ 任务进度（命令流 + 输出尾部） |
| 备份与日志 | 备份表（时间/触发/大小/条目）+ 日志表（时间/动作/结果/命令） |「恢复」（同样预检→确认）、「复制日志」 |

- 样式：沿用面板变量（`--text/--bg/--line/--radius`），直角、无图标字体、按钮用文字；
  危险按钮文字直白写后果（如「卸载 i915（会黑屏）」）。
- 文案：中文，术语保留原文（modprobe / DKMS / initramfs / MOK）。

## 六、护栏（可执行规则，不靠自觉）

| 规则 | 实现点 |
|---|---|
| 不静默动在用网卡/显卡 | `module.action` 计算 `kind=display/network && in_use` → 要求 `confirm.acknowledge` + 文字确认；拒绝时 10001 并回显后果 |
| 改动前必备份 | 所有致变动作先打包；失败即中止（不执行后续命令） |
| 不自动重启 | 只标 `effects.reboot_required`；重启与否由你在面板外决定 |
| 命令模板固定 | 全部 `args` 列表 + 白名单二进制 + `shell=False`；模块名/包名/参数值正则校验 |
| apt 不改源、不加仓库 | 代码里根本没有写 `/etc/apt/sources.list*` 的路径；缺组件只提示 |
| 不升级系统 | 只允许 `install`；`upgrade/dist-upgrade/autoremove` 不在模板表里 |
| 每步留痕 | 审计 NDJSON（命令/输出尾部/退出码/耗时/时间/触发接口/备份 id） |
| 只管自己的文件 | 只写 `rc-drivers.conf` 两个托管文件；其它 `*.conf` 只读 |
| 危险动作两阶段 | precheck（无副作用）→ apply（plan_id + 状态 hash 复核 + 显式确认） |
| 全局单飞 | 同时只跑一个改系统任务，避免 dpkg 锁冲突 |
| 明确不做 | 不动 grub/内核 cmdline；不 `dkms remove/uninstall`；不装 `.run` 第三方脚本（P4 再议）；不代做 MOK 签名 |

## 七、分阶段与验收

| 阶段 | 内容 | 验收（可执行、可复现） |
|---|---|---|
| **P1** | 体检（`drivers.overview` + `drivers.packages` 只读）+ 前端体检区块 | ① `node tools/build-extension.js drivers` 出产物；② 测试机装扩展 → `rc-ext-drivers.service` active，`/api/interfaces` 有 `drivers.overview`/`drivers.packages` 且 online；③ `invoke` 结果与同机 `lspci -nnk`、`lsmod`、`dkms status`、`dpkg -l 'firmware*'` 人工核对一致；④ **面板重启后接口自动恢复 online**（重连）；⑤ 卸载 → 单元/目录/接口全清 |
| **P2** | 模块管理 + 备份回滚（`modules`/`module.action`/`rollback`） | ① 卸载一个未使用模块 → `lsmod` 前后对照；② 黑名单写入 `rc-drivers.conf` 且 `/etc/modprobe.d` 其它文件字节不变（md5 对照）；③ 备份 → 改动 → 恢复 → 文件回到原状；④ 卸载在用模块被拒（缺确认 10001），带确认才执行 |
| **P3** | 安装 + 异步任务 + 审计（`install`/`task`/`cancel`/`log`） | ① VM 上装 `dkms`、`linux-headers-<kver>`、`firmware-iwlwifi`（源含 non-free-firmware）→ 任务日志完整（命令/退出码/耗时）；② 预检后人为改状态再 apply → 10004；③ 计划过期 → 10003；④ 并发第二个任务 → 10007；⑤ 已进入 apt 阶段取消 → 10009 |
| **P4** | 可选：第三方封装（.run/tar.gz）上传 + DKMS 构建、apt 组件开启 | 需单独设计（签名、校验、隔离、审批），默认不做 |

P1 是零风险的，做完就能用；P2 才第一次具备"改系统"的能力，所以 P2 与 P1 建议一起做、P3 单独一轮跑真机。
