# 前端开发指南(web/)

> 主系统前端: Vue3 + Vite, 源码 `web/`, 构建输出 `../public`(= Go 静态目录)。

## 1. 技术栈与命令

Vue 3 `<script setup>` + vue-router + 自建 CSS 主题类(`.section/.card/.table/.input/.btn/...`)。
```bash
cd web && node node_modules/vite/bin/vite.js build   # 输出到 main 仓库 ../public
```
前端模块无重型 UI 库(全部手写 h()/模板)。

## 3. PluginView(v4 插件加载器)

流程: route `/plugin/:name` → 拉取 `/api/plugins/<name>/assets/plugin.js`(fetch+eval 或 script 标签)
→ 读 `window.__rcPluginV4__[name].mount(el, ctx)` → 挂载 → 卸载时调用返回的清理函数。

- ctx: `{ plugin, invoke(iface,params,{timeoutMs}), on/emit, toast, navigate }`。
- 失败降级: 加载/挂载异常 → `GenericPlugin` 信息卡(不显示诊断, 诊断在服务健康页)。

## 4. api.js 现状(拆 v3 后)

- **只保留**: 系统功能(fm/term/media/envpkg/store/sysfunc/scheduler/tasks/sys)
  + 接口库 v4(ifaces/ifaceInvoke/servicesHealth/pluginInvoke) + 媒体工具(mt*/tbMedia*/vm*)。
- **已删除**(v3 网关死端点, 114+ 个): 所有 `/api/plugins/<插件名>/*` 的旧表单/GET 端点
  (tb/dc/da/hash/jm/vpn/wg/ovpn/v2/ag/up/dk/kv/mc/mcskin/bkp/ls/tg/doc/nt 等)。
- 插件页面一律经 `ctx.invoke`, **不再经过 api.js**。

## 5. 系统页开发约定

- Sidebar 项与路由一一对应(router.js 静态表)。
- 数据源唯一: `api.js` 或「接口总览」的 `system.*` 试调用; 无直接后端拼接。
- 占位/空态: `.hint`; 错误: `.err`; 载入态: loading boolean。
- **禁止**在系统页引用插件组件/插件 API; 插件只经 PluginView 动态挂载。

## 6. 服务健康中心(ServiceHealth.vue)

- 数据源: `api.servicesHealth()` → `/api/services/health`(注册表驱动)。
- 表: 名称/类型/状态/延迟/接口数; 展开行显示接口明细与日志入口。
- 已修复过 `out` 引用残留 bug(汇总卡 0 值), 修改时注意 `rows.value` 与 `summary` 同步。
