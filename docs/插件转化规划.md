# 17 插件 Vue3 + 适合语言转化规划

> 架构目标(用户明确定义):
> - **插件完全独立于主系统**: 自包含(入口/资源/前端都在插件目录), 不 import 主系统任何代码/组件
> - **主系统只负责加载**: 扫描插件目录 → 读取 plugin.json → 拉起独立子进程 → 网关代理 `/api/plugins/<name>/*` → 挂载插件前端
> - **前端统一 Vue3**: 每个插件带 `frontend/`(源码)+ 构建产物, 由面板动态加载
> - **后端用"适合语言"**: 按插件场景选语言(不强制 C++)
> - **共同数据层(可选)**: 需要数据持久化的插件经 SharedData namespace(表前缀 `ns_<name>_`), 不需要的(纯计算类)不带 db

---

## 一、架构总览(主系统 ↔ 插件边界)

```
┌───────────────────────── RainCough Core (Go 主系统) ─────────────────────────┐
│  Host 扫描 plugins/ → plugin.json → 拉起子进程 → 网关代理 /api/plugins/<n>/*  │
│  SharedData (共用数据层, 可选: 插件 db:true 时注入 RAINCOUGH_DB_DSN)          │
│  静态前端: 插件前端产物 assets/plugin.js (IIFE, window.__rcPlugin_<name>)     │
└───────────────┬──────────────────────────────────┬───────────────────────────┘
                │ 环境变量注入                     │ HTTP 网关
                ▼                                  ▼
┌─────────────────────┐  ┌─────────────────────┐  ┌─────────────────────┐
│ 插件 A (语言 X)      │  │ 插件 B (语言 Y)      │  │ 插件 C (语言 Z)      │
│ 独立进程             │  │ 独立进程             │  │ 独立进程             │
│ 自带 frontend/       │  │ 自带 frontend/       │  │ 无前端(纯工具)       │
│ db:true → SharedData │  │ db:false → 不依赖   │  │ 自包含               │
└─────────────────────┘  └─────────────────────┘  └─────────────────────┘
```

**插件协议 v3 契约**(已在用, 沿用):
```json
{
  "name": "aigen", "label": "AI 生图", "version": "2.0.0",
  "lang": "python", "entry": ["python3", "server.py"], "timeout": 30,
  "db": false, "assets": ["/frontend.html"],
  "routes": ["/ping", "/models", "/generate", ...]
}
```
- 环境变量: `RAINCOUGH_PORT`(监听 127.0.0.1:port)、`RAINCOUGH_NS`(小写名)
- db:true 时: `RAINCOUGH_DB_DSN`(共用数据库连接)
- 前端: `frontend/plugin.js` 导出 `register(window)` → `window.__rcPlugin_<name> = { mount(container, ctx) }`

## 二、17 插件现状 → 目标转化方案

### 语言判定原则
| 场景 | 适合语言 | 理由 |
|---|---|---|
| 计算/数据处理/机器学习 | Python | 生态最全(Pillow/diffusers/tesseract 桥接) |
| 系统管理/高并发/常驻 CLI | Go | 单二进制、并发强、无解释器依赖 |
| 原有 C++ 高性能组件 | C++ | 保留(如 uptime-cpp 探活) |
| 纯 IO/网络抓取 | Python 或 Go | 按团队熟练度 |

## 三、Vue3 插件前端规范(每个插件)

```
plugins/<name>/
├─ plugin.json             # 协议 v3
├─ server.py|server.go     # 后端入口(独立进程)
├─ frontend/
│   ├─ plugin.js           # 源码: register(window) → __rcPlugin_<name>
│   └─ (可选) assets/      # 静态资源
└─ assets/plugin.js        # 构建产物(esbuild IIFE, external vue)
```

**plugin.js 契约**(uptime 已验证):
```js
export function register(window) {
  window.__rcPlugin_uptime = {
    mount(container, ctx) {
      // ctx: { plugin, api } — api 为面板注入的请求器(指向 /api/plugins/<name>/*)
      // 在此用 Vue h()/VueDOM 渲染或 CDN Vue; esbuild external vue 由面板运行时注入
      container.innerHTML = '<div>...</div>'
      // 或 createApp(...).mount(container)
    }
  }
}
```

**构建**: `tools/build-plugin-frontend.js`(esbuild, external vue)→ `assets/plugin.js`
**面板加载**: `PluginView.vue` 动态 `import('/api/plugins/<name>/assets/plugin.js')`→ 调 `mount(container, {plugin, api})`

## 五、风险与决策点
- **语言切换的收益/成本**: docker/kvm/mcserver/vpn 从 Python→Go 收益是常驻更稳, 但重写成本高——**建议先 Vue3 前端 + Python 保持功能, Go 化列为二期优化**, 避免一次大爆炸
- **依赖**: Python 插件依赖(如 diffusers)大, 保留 Python 合理; Go 化仅对 CLI/进程管理类
- **前端复用**: 旧面板 components/ 各插件组件(95 个文件)是**前端 UI 蓝本**, 转化时把其中对应页面逻辑改写为 plugin.js 挂载式(不复制后端耦合)
- **db 选配**: 只有 JMComic/uptime/vpn/mcserver/laizhangsetu 需要持久化 → db:true + SharedData; 其余纯工具不依赖

---
**下一步建议**: 从 P0(uptime 已就绪)→ P1 六插件(前端优先, 后端语言保持 Python 同时插 件规范对齐), 每完成一个插件都过一遍"独立进程 + 网关 + Vue3 挂载 + 数据"全链路验证, 逐一向你确认。
