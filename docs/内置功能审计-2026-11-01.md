## 二、修掉的问题

### 2.1 严重：插件启停完全没有 UI

- `supervisor` 有 `StartPlugin` / `StopPlugin` / `RestartPlugin` / `SetAutostart`
- 后端有 `/api/services/action`、`/api/services/autostart`
- **前端一次都没调用过**（`serviceAction` 有定义、零引用）

后果：
- 插件崩了只能重启整个面板
- 新装插件默认不开自启，面板一重启它就静默停着（当天 QQBot 实测踩到）

附带发现的错签名：

```js
// 旧：v3 的 systemd 单元模型，后端按 {name, action} 解析，传 unit 会得到空名 → 400
serviceAction: (unit, action) => req('POST', '/api/services/action', { unit, action })
```

因为从来没人调用，这个错一直没暴露。

**修复**：签名改 `(name, action)`；新增 `serviceAutostart` / `serviceLog`；
「插件」页每行加「管理」面板 —— 启动 / 停止 / 重启、开机自启开关、最近 200 行运行日志。

### 2.2 严重：插件运行日志没有入口

`supervisor` 一直写 `.runtime.log`，`/api/services/log` 也早就存在，但没有任何页面能看。
排查 QQBot 时只能进终端 `tail` 文件。现已接入「管理」面板。

### 2.3 无效按钮：设置页的「密钥」

闸门在 2026-11-01 改为**默认关闭**后，设置页仍无条件渲染密钥输入框与「解锁」按钮 ——
用户会看到一个输了也没用的密码框。现在整块按 `gateEnabled` 隐藏，并说明如何真正启用。

### 2.4 重复按钮：「打开」与「设置」指向同一处

插件列表行里两个按钮都调 `open(p.name.replace…)`，点了效果完全一样。
「设置」实际是插件自己的页面内容。已把「设置」换成「管理」（启停/自启/日志）。

### 2.5 死代码：`handleStoreProject`（22 行）

从未在 `mux` 注册过路由，注释却写着"归 404 而不是返回假数据"，让人以为它还活着。
已删除，并留注释说明面板更新只走 `/api/panel/update/*`。

### 2.6 死配置：8 个字段设了不起作用

| 字段 | 来源 | 实际情况 |
|---|---|---|
| `DBPoolSize` / `DBQueryTimeout` | `RC_DB_POOL_SIZE` / `RC_DB_QUERY_TIMEOUT` | v3 的 DB 池，现走 sqlite KV |
| `PluginHostPort` / `PluginStartTimeout` / `PluginMaxChildren` / `PluginKeepalive` / `PluginProxyTimeout` | `RC_PLUGIN_*` | v3 的子进程池模型，v4 由 supervisor 管理 |
| `SudoPW` | `RC_SUDO_PW` / `TOUCHGAL_SUDO_PW` | **读一个 sudo 密码，全仓从未使用** |

全部删除（保留真正在用的 `PluginRestartMax`）。
`SudoPW` 尤其该删：一个"看起来存着 root 密码"的死字段，比没有这个字段更危险。

### 2.7 死代码：14 个前端 API 方法

`ifaces` / `ifaceDetail` / `ifaceInvoke` / `diskUnmount` / `netStatus` / `fmDelete` /
`fmRead` / `fmOpsDownload` / `tmHostSort` / `storeChangelog` / `panelInstallCommand` /
`panelUpdateLog` / `servicesHealthLog` / `ifacesSummary`(误删后恢复，见 §3)

其中 `fmDelete` 与 `servicesHealthLog` 是被新接口取代的旧版本，其余对应的页面/功能不存在。

### 2.8 硬编码版本号

`Sidebar.vue` 里写死 `v1.0.0-beta.2`，升版本要改四处（VERSION / config.go / package.json / 这里）。
改为读 `GET /api/panel/version`。

## 四、补上的能力

### 4.1 面板更新支持「本地上传包」

在线更新只认 GitHub Release 资产。自己构建的版本（改了代码但没发版）永远进不去，
只能手工 scp 二进制 + `systemctl restart`。

新增 `POST /api/panel/update/upload`（multipart，`.tar.gz`，上限 256MB）：

```
改代码 → 构建 → 打包(tar.gz) → 面板里上传 → 确认重启
```

落盘 / 解包 / 校验 / 备份 / 覆盖 / 回滚与在线更新**共用同一实现** `applyPanelArchive`，
两条路径不会漂。前端在「面板更新」浮窗里加了「上传面板包更新…」。

### 4.2 回滚入口

后端 `POST /api/panel/update/rollback` 一直存在，但没有任何 UI ——
自更新系统不给退路很危险：新版本起不来时只能 ssh 手工救。
浮窗里新增「回滚到上一版本」（两次点击确认，备份路径来自 `updateState`）。

## 六、发现但未改（需要产品决策）

1. **JMComic 声明 `rest_public: true`** —— 其 REST 路由免登录暴露到局域网（漫画图片/元数据）。
   代码注释自己警告过"把插件数据无门槛暴露到局域网是实打实的隐私风险"，
   但很可能是移动端 JMReader 依赖的，改了会废掉阅读器。
2. **`/api/terminal/ws_token`、`/api/disks/unmount`、`/api/net/status`、
   `/api/store/changelog`、`/api/services/health/log`** 等后端路由无前端入口。
   保留理由：可能是外部客户端/脚本在用；删路由的收益低于误伤成本。
3. **QQBot 接手文档第 7 条**说 `main.css` 的 `.error` 带 `padding:24px;text-align:center`，
   现状已不是。属于文档过期（不影响功能），改文档时一并同步。
