# 系统扩展「驱动」· 无头矿卡与魔改驱动设计（v2）

> 需求：「需要魔改驱动，用于 P104、P106、30HX 这些无头卡」。
> 你的三个决定（本轮确认）：**① 有目标机器，但尚未安装面板；② 用途是 AI 推理/渲染计算，不接显示器；
> ③ 魔改驱动由你准备好后上传到 `https://gitee.com/dtxcr/rain-cough`，扩展从该仓库拉取安装。**
>
> 配套：[扩展-驱动-设计方案.md](扩展-驱动-设计方案.md)（v3 机制与接口）、
> [扩展-驱动-功能设计.md](扩展-驱动-功能设计.md)（功能与界面）。
> v1 里"官方 `.run` + 本地补丁"仍是可选路线；v2 以**你自己的 Gitee 驱动仓库**为主来源。
> 本文只写设计，代码未动。

## 一、结论摘要

1. 驱动来源分两条路线，**扩展都支持，走哪条由仓库清单决定**：
   - **路线 A（省配额）`patch-script`**：Gitee 只放**补丁脚本/补丁数据**（KB 级），扩展从 **NVIDIA 官方**下载
     `.run` 再本地打补丁 → 几乎不占 Gitee 配额，且不依赖任何第三方打包的驱动二进制。
   - **路线 B（你现在的计划）`nvidia-run`**：Gitee 发行版放**打好补丁的完整驱动**，扩展分卷下载后直接安装
     → 单文件必须 ≤100MB，因此**必须分卷**；一个驱动 397–530MB，占满仓库 1GB 附件配额的 40%–53%。
2. 因此仓库里除了驱动本体，还要有一份**清单 `drivers/registry.json`**（几 KB，走仓库文件，不受附件配额影响）：
   声明每个驱动对应哪些卡（PCI ID）、版本、分卷清单与 sha256、前置依赖、安装后动作（关 GSP / 黑名单 nouveau）、
   是否需要重启。**扩展只认这份清单**，不猜文件名。
3. 新增两个接口 `drivers.repo`（只读：仓库/清单/条目）与 `drivers.repo.config`（main：配 URL/分支/token，只写不读），
   加上 v1 的 `drivers.gpu`（只读体检）。安装仍复用 `drivers.install`（新增 `kind:"mod"` = 来自仓库的魔改驱动）。
4. 计算用途（不接显示器）下，v1 的"显示提供者"矩阵**降为版本偏好提示**，不再阻断安装；
   重点转为：驱动装完可用、`nvidia-smi` 认卡、算力/显存/CUDA 能力可得、**重启后仍生效**（模块换代必须重启）。
5. 目标机器**还没装面板** → 先装面板（Debian 12 / Ubuntu 22.04），再装本扩展，再配驱动仓库。
   本文 §十 给出装机顺序。

### 2.2 「魔改驱动」的本质与版本矩阵（外部来源，实施前需复核）

来源：[dartraiden/NVIDIA-patcher · Linux 说明](https://github.com/dartraiden/NVIDIA-patcher/blob/master/docs/README-LINUX.md)、
[自打补丁说明](https://github.com/dartraiden/NVIDIA-patcher/blob/master/docs/README-PATCHER-LINUX.md)。

- 本质：**官方 `.run` 驱动里的内核模块二进制补丁**（`nv-kernel.o_binary`），让矿卡这类非零售型号能正常启用 3D/加速；
  上游也提供"预打包补丁文件"那条路。
- 版本矩阵（按"用哪块 GPU 显示画面"选版本）：P1XX → `580.178.04`（任意显示提供者）；
  CMP 及其它 → 显示由 iGPU/AMD/NVIDIA Turing+ 提供 → `615.71.09`，由 Maxwell–Pascal 提供 → `580.178.04`，
  由 pre-Maxwell 提供 → `470.256.02`（**无需补丁**）。
  **你这台机器是纯计算用途**（显示器接别处或走远程）→ 按"iGPU/AMD/Turing+/none"列取：
  P1XX = 580.178.04，CMP = 615.71.09。此矩阵在本设计里只作**版本偏好与告警**（仓库给什么版本就装什么，
  与矩阵不符时在计划里提示）。
- CMP 30HX/40HX：建议**关闭 GSP 固件**（`options nvidia NVreg_EnableGpuFirmware=0`）+ blacklist nouveau；
  校验 `nvidia-smi -q | grep -i gsp`。
- CMP 的 x16 PCIe 宽度需硬件焊补件解锁 —— 只显示事实，不参与。

## 三、Gitee 驱动仓库设计（主来源）

### 3.1 仓库结构

```
rain-cough/
├─ README.md
└─ drivers/
   ├─ registry.json          ← 清单：扩展只认这个（KB 级，走仓库文件）
   ├─ README.md              ← 给人看的上传/维护说明
   └─ patch/                 ← 仅"路线 A"用：补丁脚本（KB~MB 级，可选）
发行版（Releases）附件：分卷的驱动本体
   标签示例  mod-580.178.04  →  NVIDIA-Linux-x86_64-580.178.04-patched.run.part.aa … .part.ae
   标签示例  mod-615.71.09  →  NVIDIA-Linux-x86_64-615.71.09-patched.run.part.aa … .part.af
```

| 字段 | 约束 |

| `type` | 只能是 `nvidia-run` \| `patch-script`（**不接受任意命令/任意脚本类型**） |

| `release_tag` | `^[A-Za-z0-9._-]{1,64}$` |
| `post[]` | 只能取固定枚举：`blacklist-nouveau`、`gsp-off`、`initramfs`、`depmod`（**不接受自由文本命令**） |
| `patch.expect` | 数组，`dry-run` 命中数必须逐条一致，否则中止 |

### 3.3 扩展怎么取（接口与 URL，实测过形态）

| 用途 | 地址 |
|---|---|
| 读清单（公开仓库直读） | `https://gitee.com/dtxcr/rain-cough/raw/<branch>/drivers/registry.json` |
| 读清单（私有仓库带令牌） | 同上 + `?access_token=<token>`；或 `https://gitee.com/api/v5/repos/dtxcr/rain-cough/contents/drivers/registry.json?ref=<branch>`（base64） |
| 列发行版（取附件名/下载地址） | `https://gitee.com/api/v5/repos/dtxcr/rain-cough/releases`（实测匿名可读，当前 `[]`） |
| 下载分卷 | `https://gitee.com/dtxcr/rain-cough/releases/download/<tag>/<part>` |

- 分支默认 `main`；`default_branch` 为空（空仓库）时扩展提示"仓库还没有内容"，不报错崩。
- 令牌：仓库当前是公开的 → **默认不需要令牌**；私有化后可在扩展页面填（只写不读，0600 存
  `<扩展目录>/.data/repo.json`）。**面板二进制不需要改**（要改就违背了"扩展自带一切"的原则）。
- 缓存：清单缓存 10 分钟（手动「同步」可强制刷新）；分卷下载缓存到 `<扩展目录>/.data/repo/<id>/`，
  装完可按策略保留或删除（默认保留最近 1 个，其余删）。

### 3.4 配额怎么活下来（给你上传时的硬约束）

| Gitee 配额 | 限制 | 我们的用法 |
|---|---|---|
| 仓库单文件 | 50MB | 仓库里只放 `registry.json` + 补丁脚本（KB 级） |
| 单仓库容量 | 500MB | 不往仓库树里放大文件 |
| 发行版附件单文件 | 100MB | 分卷 **≤95MB**（留余量） |
| 单仓库附件总量 | 1GB | P1XX(397MB)+CMP(530MB)=927MB → **只传你需要的那套**，或开第二个仓库 |
| 账号总容量 | 5GB | 多仓库场景注意 |

- **多来源**：`drivers.repo.config` 支持配置**多个仓库**（如 `rain-cough` + `rain-cough-drivers-2`），
  清单合并、按卡去重（同卡多条目时按版本号/来源优先级选择，并在计划里显示来源）。
- 分卷方式与校验：`split -b 95M <file> <file>.part.`（建议后缀 `.part.aa/.ab/...`，便于排序）；
  扩展按 `parts[]` 顺序下载 → 逐卷 sha256 → 拼接 → 整体 sha256 → 再安装。任一不符即中止并清理。

### 3.5 信任模型（因为你上传的是"魔改"二进制，必须写清）

1. **信任锚 = 你自己的 Gitee 账号**（仓库归属你；扩展只从清单给的 URL 下载，不跳转到其它域名）。
2. **传输与完整性**：逐卷 sha256 + 整体 sha256（清单里带）；Gitee 走 HTTPS；下载后先校验再执行。
3. **执行面**：清单不能给任意命令——`type` 只有两种固定实现，`post[]` 只有四个固定动作，
   分卷名做路径安全校验（禁 `/`、`..`）。**清单被篡改也换不来任意 root 命令**。
4. **可选强校验**：清单支持 `gpg_sig`（对 `registry.json` 与各分卷的 detached 签名）与
   `gpg_key_fingerprint`（pin 在扩展内的公钥指纹）；你要用我就实现（默认不启用）。
5. **透明**：预检面板显示来源 URL、每个分卷的大小/sha256、将执行的**固定**命令序列、将写哪些文件、
   退路三条；日志留痕（含 sha256 与补丁报告）。
6. **降级**：清单/附件不可达时，仍可用 v1 的"官方 `.run` + 上游补丁脚本"路线（pin commit + sha256 + dry-run）。

## 五、安装流程

### 5.1 复用 `drivers.install`，新增 `kind:"mod"`

| kind | 语义 |
|---|---|
| `mod` | 来自驱动仓库（清单条目）的魔改驱动；`type=nvidia-run` 走分卷下载安装，`type=patch-script` 走官方下载+本地补丁 |
| `nvidia-run` | （保留）直接给官方 `.run` URL 安装，非矿卡 NVIDIA 卡用 |
| `nvidia-patch` | （保留）官方 `.run` + 上游补丁脚本，仓库不可达时的兜底 |

### 5.2 执行序列（异步任务，每步写审计）

1. **备份**：`/etc/modprobe.d`、`/etc/modules-load.d`、`/etc/modules`、`/etc/default/grub`（快照，不改）、
   `dpkg -l 'nvidia*' 'libnvidia*'`、`lsmod | grep -E 'nvidia|nouveau'`、`nvidia-smi -q`（若有）。
2. **前置**：`apt-get install -y --no-install-recommends xxd dkms linux-headers-$(uname -r) build-essential`（按需）。
3. **取驱动**
   - `nvidia-run`：逐卷下载（断点续传，单卷超时 600s）→ 逐卷 sha256 → 拼接 → 整体 sha256 →
     `chmod +x` → `sh <file> --check`。
   - `patch-script`：NVIDIA 官方 `.run` 下载（`--check`；若清单给了 `sha256_expected` 则比对）→
     `--extract-only` → 取补丁脚本（sha256 校验）→ **dry-run**（逐 pattern 命中数必须一致）→ 真打补丁 → 补丁报告。
4. **移除冲突包**：按 `conflicts` 执行 `apt-get remove --purge <pkg...>`。
5. **安装**：`./nvidia-installer --silent --no-questions --ui=none --dkms`（日志另存 `/var/log/nvidia-installer.log`）。
6. **收尾（固定枚举动作）**：写托管 `/etc/modprobe.d/rc-drivers.conf`（`blacklist nouveau`；CMP 30HX/40HX 追加
   `options nvidia NVreg_EnableGpuFirmware=0`）→ `depmod -a` → `update-initramfs -u -k all`。
7. **校验**：`nvidia-smi -L`、`nvidia-smi --query-gpu=name,driver_version,compute_cap,memory.total --format=csv`、
   `nvidia-smi -q | grep -i gsp`、`/proc/driver/nvidia/version`、`dkms status` → 全写进任务结果。
8. **收尾**：标 `reboot_required: true`，**不自动重启**；按策略处理下载缓存；刷新 `drivers.gpu`/`overview`。

### 5.3 退路（三条，都在界面里）

1. `[官方卸载]` `/usr/bin/nvidia-uninstall --silent` → 恢复托管文件 → `update-initramfs -u -k all`；
2. `[回 Debian 包]` `apt-get install nvidia-driver`（显示将安装版本）；
3. `[重装同条目]` 用已缓存的分卷/官方 `.run` 重跑（保留下载时可用，无需重新下一遍 400MB）。

## 六、安全护栏（v1 的 9 条 + 仓库模式 4 条）

| 规则 | 实现点 |
|---|---|
| 清单不可执行任意命令 | `type` 两种固定实现；`post[]` 四个固定动作；分卷名路径安全校验 |
| 只从清单给的 Gitee URL 下载 | 不跟随跳转到其它域名；下载 URL 必须与仓库域一致（`gitee.com` / `*.gitee.com`） |
| 下载先校验后执行 | 逐卷 + 整体 sha256；`--check`；任一不符即中止并清理 |
| 可选 GPG 强校验 | `gpg_key_fingerprint` pin 在扩展内，签名不符即拒绝（默认关，你要就开） |
| 供应链（v1 保留） | 默认仍**不下载来源不明的第三方驱动**；Gitee 仓库是你自己的账号，属显式信任来源 |
| Secure Boot 开 → 拒绝 | 不代签 MOK，只给可复制命令 |
| 改动前必备份 | 失败即中止；退路三条 |
| 不自动重启 / 不改 GRUB / 不刷 vBIOS / 不焊接 | cmdline 版本只给可复制命令；硬件操作只显示事实 |
| 只写自己的文件 | `/etc/modprobe.d/rc-drivers.conf`、`/etc/modules-load.d/rc-drivers.conf` 两个托管文件 |

## 八、验证方案（没有矿卡也能验全流程）

后端 fixture 模式：`RC_DRIVERS_FAKE_ROOT=<目录>`（伪 `sys/`、`etc/`、`lib/firmware/`、`pci.ids`）+
`RC_DRIVERS_FAKE_CMD=<命令回放表>` + **`drivers.repo.config` 支持 `local_dir`**（用本地目录冒充仓库：
`registry.json` + 分卷文件）→ 无需 Gitee、无需显卡即可端到端验证。

| fixture | 内容 | 期望 |
|---|---|---|
| F1 | P106-100 + 无显示 + 缺 dkms/xxd | 识别矿卡 P1XX；`preferred_version=580.178.04`；issues 列前置；计划正确 |
| F2 | CMP 30HX | `preferred_version=615.71.09`；`post` 含 `gsp-off`；计划显示 GSP 关闭行 |
| F3 | 已装 Debian `nvidia-driver 535.309.01` | 冲突列出；计划含 `apt-get remove --purge`；退路含"回 Debian 包" |
| F4 | Secure Boot 开 | `blocked_by=["secure-boot"]`，apply 被拒 |
| F5 | 清单条目 `card_pci_ids` 与本机卡不匹配 | 条目不出现（或标"不适用本机"），不误装 |
| F6 | 分卷 sha256 故意写错 / 少一卷 | 下载阶段失败并清理，**不进入安装** |
| F7 | `type=patch-script` + dry-run 命中数不符 | 任务失败，报"补丁与驱动版本不匹配"，不安装 |
| F8 | `post[]` 含未枚举动作 / 分卷名含 `..` | 清单条目被拒（校验失败并显示原因） |
| F9 | 仓库不可达（断网/空仓库） | 界面显示仓库状态与最近一次缓存时间；不影响体检与模块功能 |

真机验收（目标机器，装好面板后）：① 只读体检与 `lspci -nnk`、`nvidia-smi -L` 人工核对；
② 配仓库 → 同步清单；③ 装前置（xxd/dkms/headers）；④ 装魔改驱动 → 校验 → **重启** → 再体检确认
`nvidia-smi` 认卡、`compute_cap` 正确；⑤ 退路三条各测一次。

## 十、装机顺序（目标机器还没有面板）

1. 目标机器装 **Debian 12（推荐，与开发机一致）或 Ubuntu 22.04**，关闭 Secure Boot（魔改驱动是未签名模块）。
2. 用面板安装命令装面板：`curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/fongwuyan/RainCough-panel-web/v1.0.0/install.sh | bash`
   （版本号仍 1.0.0；若该机器在国内，走 gh-proxy 镜像）。
3. 面板 →「系统扩展」→ 安装 **drivers** 扩展（机制已就绪：装完自动生成 `rc-ext-drivers.service` 并注册接口）。
4. 打开「驱动」页 → 只读体检（看内核/headers/dkms/xxd/Secure Boot/卡是否被识别）。
5. 配「驱动仓库」（URL `https://gitee.com/dtxcr/rain-cough`、分支 `main`）→ 同步清单。
6. 预检 → 确认安装前置（xxd/dkms/headers）→ 预检 → 确认安装魔改驱动。
7. **重启**（模块换代必须重启）→ 再看体检：`nvidia-smi` 认卡、`compute_cap` 6.1/7.5/8.6、显存与链路。
8. （可选，默认不做）容器直通：需要加 NVIDIA 官方容器仓库 → 与"不加第三方仓库"护栏冲突，**要你明确同意才做**。
