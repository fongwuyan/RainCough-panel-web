# 系统扩展「驱动」· 无头矿卡与魔改驱动设计（v1）

> 需求来源：「需要魔改驱动，用于 P104、P106、30HX 这些无头卡」。
> 配套文档：[扩展-驱动-设计方案.md](扩展-驱动-设计方案.md)（v3 机制与接口）、
> [扩展-驱动-功能设计.md](扩展-驱动-功能设计.md)（功能与界面行为）。
> 本文把 v3 里推到 P4 的「第三方/魔改驱动」正式立项，并把矿卡识别、驱动版本选择、补丁流程、护栏、验证方案定下来。
> 本文只写设计，代码未动。

---

## 一、结论摘要

1. **矿卡（P102/P104/P106/CMP 全系）在 Linux 上不是"装不上驱动"，而是"官方驱动里这类非零售型号的 3D 加速被禁用"**；
   解决办法是官方 `.run` 驱动 + **对驱动内核模块二进制做字节补丁**（社区 patcher 的做法），不是随便找个第三方驱动包装上。
2. 因此本扩展的魔改路线定为：**NVIDIA 官方 `.run`（从 NVIDIA 官方 URL 下载，校验 `--check` + sha256）
   → `--extract-only` → 本地跑补丁脚本（pin 到具体 commit + sha256 + 逐 pattern 命中数校验，先 dry-run）
   → `nvidia-installer` 安装**。默认**不下载任何第三方打包好的驱动二进制**（供应链风险）。
3. 驱动版本不是随便挑：**必须同时支持"矿卡"和"这台机器用来显示输出的那块 GPU"**，所以体检要先判定
   `display_provider`（iGPU / AMD / NVIDIA Turing+ / NVIDIA Maxwell–Pascal / pre-Maxwell）。
4. Debian 12 自带 `nvidia-driver` 只有 **535.309.01**，低于魔改矩阵要求的 580/615 分支 →
   魔改路线**必须走官方 `.run`**，并处理与 Debian 包的冲突（计划里显式列出将移除的包）。
5. 新增一个只读接口 `drivers.gpu`（矿卡专项体检 + 路线推荐）；安装复用 `drivers.install`，新增
   `kind:"nvidia-run"` 与 `kind:"nvidia-patch"`，走既有的 precheck → apply → task 异步模型。

### 2.2 「魔改驱动」到底是什么（外部来源）

来源：[dartraiden/NVIDIA-patcher · Linux 说明](https://github.com/dartraiden/NVIDIA-patcher/blob/master/docs/README-LINUX.md)
与 [自打补丁说明](https://github.com/dartraiden/NVIDIA-patcher/blob/master/docs/README-PATCHER-LINUX.md)
（本轮抓取；**实施时必须重新核对版本矩阵与补丁目标文件**，下面的版本号按当前上游为准）。

- 作用：为 P106-090/P106-100/P104-100/P104-101/P102-100 + CMP 30HX/40HX/50HX/70HX/90HX/170HX
  等矿卡**开启 3D 加速支持**。
- 安装方式（上游给的两条路）：
  1. 用上游发布的**预打包补丁文件**替换官方驱动解包后的文件，再 `nvidia-installer`；
  2. 用上游的 `linux.sh` **在自己解包的官方驱动上打补丁**（脚本会先备份 `nv-kernel.o_binary`，
     逐条 pattern 命中后输出 `=== SUCCESS ===`），然后 `nvidia-installer`。脚本依赖 `bash/coreutils/grep/sed/xxd`。
- **驱动版本矩阵**（上游表格，按"用什么设备显示画面"决定）：
  - P1XX 矿卡：580.178.04（iGPU / AMD / NVIDIA Turing+ / Maxwell–Pascal 都可用这一版）
  - CMP 及其它：显示由 iGPU / AMD / NVIDIA Turing+ 提供 → 615.71.09；显示由 NVIDIA Maxwell–Pascal 提供 → 580.178.04；
    显示由 pre-Maxwell 提供 → 470.256.02（**无需补丁**）
- CMP 30HX / 40HX 额外建议：**关闭 GSP 固件**（默认开启会掉 3D/计算性能与稳定性）——
  `/etc/modprobe.d` 写 `options nvidia NVreg_EnableGpuFirmware=0`（上游还建议内核 cmdline 同名参数 + `update-grub`），
  并 blacklist nouveau。校验：`nvidia-smi -q | grep GSP`。
- CMP 卡的 x16 PCIe 宽度需要**焊接补件**才能解锁 —— 硬件操作，本扩展**只显示事实，不参与**。

### 2.3 官方驱动下载可用性（本轮实测，宿主直连）

`https://download.nvidia.com/XFree86/Linux-x86_64/<ver>/NVIDIA-Linux-x86_64-<ver>.run`：

| 版本 | HTTP | 大小 |
|---|---|---|
| 580.178.04 | 200 | 397,214,534 B（≈379 MB） |

### 2.4 本机环境实测（决定流程细节）

| 项 | 实测 | 影响 |
|---|---|---|
| `xxd` | **未安装** | 补丁脚本依赖它 → 流程第 2 步装 `xxd` |
| `dkms` | **未安装** | 官方 `.run` 若要 `--dkms`（内核升级后免重装）先装 dkms；否则每次内核升级都要重装驱动 |
| `gcc` / `make` | 已装 | 可编译内核模块 |
| `curl` / `sha256sum` / `tar` | 已装 | 下载与校验 |
| Secure Boot | **已关闭**（efivar 第 5 字节 = 0） | 未签名内核模块可加载；若开启 → **直接拒绝并说明** |
| `/sys/class/drm` | 只有 `card0`（Intel iGPU）+ `DP-1`/`HDMI-A-1`/`HDMI-A-2`，**全部 disconnected** | 显示提供者无法靠连接器状态判定 → 必须回退到"内核驱动 + 设备类别"判定并允许手选 |
| 本机 NVIDIA 硬件 | 无（`lspci` 仅 Intel `8086:162b`） | 这台机器**只能做 fixture 验证**，真机验收必须有插了矿卡的机器 |

### 3.2 显示提供者判定（顺序，判定不出就要你选）

1. `/sys/class/drm/card*-*/status` 里有 `connected` 的连接器 → 该连接器所属 card 的驱动与型号即提供者（confidence=high）。
2. 无 `connected`（本机就是这个情况：三路全 disconnected）→ 用"有输出连接器的 card" + 其内核驱动判定（confidence=low）：
   `i915/amdgpu/radeon/nouveau/nvidia` → 对应类别。
3. 机器上**没有任何带输出连接器的 card**（纯计算卡服务器）→ `kind:"none"`。
4. 判成 `low` 或 `none` 时：预检面板要求**手选**"显示输出设备"（下拉列出所有 card），
   选择结果写进计划并在 `why` 里注明"由你指定"。**不猜**。

|---|---|---|---|
| P1XX（P102/P104/P106） | 任意 | 580.178.04 | 需要 |
| CMP / 其它矿卡 | iGPU / AMD / NVIDIA Turing+ / none | 615.71.09 | 需要 |
| CMP / 其它矿卡 | NVIDIA Maxwell–Pascal | 580.178.04 | 需要 |
| CMP / 其它矿卡 | NVIDIA pre-Maxwell | 470.256.02 | **不需要**（官方即可） |

- Secure Boot 开 → `blocked_by: ["secure-boot"]`（拒绝并由你决定关 Secure Boot 还是走 MOK 签名，二者都不代做）。
- 已装 Debian 包驱动 → `conflicts.deb_nvidia` 非空，计划含移除步骤。
- `dkms`/`headers`/`xxd` 缺 → 计划自动带前置安装步骤（不需要你是专家）。

## 四、安装流程设计

### 4.1 复用 `drivers.install`，新增两个 kind

| kind | 语义 |
|---|---|
| `nvidia-run` | 官方 `.run` 原样安装（非矿卡的 NVIDIA 卡也用这条；`kind:"vendor"` 的 NVIDIA 细分） |
| `nvidia-patch` | 官方 `.run` + 本地字节补丁（矿卡走这条） |

`precheck` 返回的 plan 在上述通用字段之外增补：

```json
{ "kind": "nvidia-patch",
  "download": { "url": "https://download.nvidia.com/XFree86/Linux-x86_64/580.178.04/NVIDIA-Linux-x86_64-580.178.04.run",
                "size_b": 397214534, "sha256_expected": "<内置固定值>", "verify": ["sh --check", "sha256sum"] },
  "patch": { "tool_url": "https://raw.githubusercontent.com/dartraiden/NVIDIA-patcher/<commit>/linux.sh",
             "tool_commit": "<pin>", "tool_sha256": "<pin>",
             "target": "nv-kernel.o_binary",
             "expect": [ { "pattern": 1, "hits": 1 }, { "pattern": 2, "hits": 1 } ],
             "dry_run_required": true },
  "conflicts": [ { "pkg": "nvidia-driver", "version": "535.309.01", "action": "remove" } ],
  "prereq": [ "xxd", "dkms", "linux-headers-6.1.0-52-amd64", "build-essential" ],
  "modprobe": { "file": "/etc/modprobe.d/rc-drivers.conf",
                "lines": [ "blacklist nouveau", "options nouveau modeset=0",
                           "options nvidia NVreg_EnableGpuFirmware=0" ] },
  "side_effects": { "nouveau_blacklist": true, "initramfs": true,
                    "display_may_break": false, "reboot_required": true },
  "rollback": { "uninstaller": "/usr/bin/nvidia-uninstall",
                "restore_deb": "apt-get install nvidia-driver", "backup_required": true },
  "requires_confirm": ["nvidia-run-install", "reboot-required"] }
```

### 4.2 执行序列（异步任务；每步写审计）

1. **备份**：`/etc/modprobe.d`、`/etc/modules-load.d`、`/etc/modules`、`/etc/default/grub` 快照、
   `dpkg -l 'nvidia*' 'libnvidia*'`、`lsmod | grep -E 'nvidia|nouveau'`、`nvidia-smi -q`（若有）。
2. **前置**：`apt-get install -y --no-install-recommends xxd dkms linux-headers-$(uname -r) build-essential`（按需）。
3. **下载**官方 `.run` 到 `<扩展目录>/.data/nvidia/`（curl 支持续传，超时 1800s）→ `sh <file> --check` +
   sha256 比对（不符 → 删文件、失败退出）。
4. **解包**：`sh <file> --extract-only` → `NVIDIA-Linux-x86_64-<ver>/`。
5. **补丁**（仅 `nvidia-patch`）：按 pin 的 commit 取补丁脚本（或用手放进 `.data/nvidia/linux.sh` 的副本）→
   sha256 校验 → **dry-run**（逐 pattern 命中数必须与 `expect` 一致）→ 真打补丁 → 记录补丁前后
   `nv-kernel.o_binary` 的 sha256 与改动字节数（补丁报告，进审计日志）。
6. **移除冲突包**：按 plan 列的 `conflicts` 执行 `apt-get remove --purge <pkg...>`。
7. **安装驱动**：在解包目录跑 `./nvidia-installer --silent --no-questions --ui=none [--dkms]`；
   输出全量进任务日志（安装器日志另存 `/var/log/nvidia-installer.log`）。
8. **托管模块参数**：写 `/etc/modprobe.d/rc-drivers.conf`（nouveau 黑名单；CMP 30HX/40HX 追加 GSP 关闭行），
   `depmod -a`，`update-initramfs -u -k all`。
9. **校验**：`nvidia-smi -L`（卡是否被识别）、`nvidia-smi -q | grep -i gsp`、
   `cat /proc/driver/nvidia/version`、`dkms status`（若用 dkms）→ 全部写进任务结果。
10. **收尾**：标记 `reboot_required: true`，**不自动重启**；刷新 `drivers.gpu`/`overview`。

### 4.3 卸载与回滚（三条退路，都在界面里）

1. **卸载官方驱动**：`/usr/bin/nvidia-uninstall --silent`（若存在）→ 恢复托管文件 → `update-initramfs -u -k all`。
2. **回到 Debian 包驱动**：`apt-get install nvidia-driver`（计划里给出确切命令）。
3. **回到补丁前状态**：任务记录里保留补丁前 `nv-kernel.o_binary` 的 sha256 与备份路径，
   可从 `.data/nvidia/` 的原始解包副本重新走一遍（脚本自身也留了 `nv-kernel.o_binary.backup`）。

## 五、安全护栏（在 v3 §六 之上新增/收紧）

| 规则 | 实现点 |
|---|---|
| **不下载第三方打包的驱动二进制**（默认） | 只从 `download.nvidia.com` 取官方 `.run`；补丁在本地跑；`allow_prebuilt` 默认 false，打开需二次确认并显示来源/大小/sha256 |
| **补丁可复核** | 补丁脚本 pin commit + sha256；逐 pattern 命中数校验；先 dry-run；输出"改了几个字节、改了哪几个文件"的报告 |
| **不看不懂的补丁不跑** | `expect` 与上游不一致（版本漂移）→ 中止并报"补丁与驱动版本不匹配，需更新补丁定义" |
| **Secure Boot 开 → 拒绝** | 不做 MOK 代签；只给可复制命令 |
| **显示风险显式确认** | 若 `display_provider` 就是要替换驱动的那张卡（或系统唯一显示设备是 NVIDIA 卡）→ 计划强制含 `display-risk` 确认，文案写明「执行后可能黑屏，需具备 SSH/串口访问」 |
| **不自动重启** | 只标 `reboot_required`（驱动换代必须重启才生效） |
| **不改 GRUB** | GSP 关闭默认走托管 `modprobe.d`；上游建议的 `nvidia.NVreg_EnableGpuFirmware=0` cmdline 版本只给**可复制命令** |
| **不刷 vBIOS、不焊接** | 只显示事实（PCIe 宽度、需要焊接解锁）与外部说明入口，不提供任何执行路径 |
| **内核升级后** | 默认 `--dkms`（需先装 dkms）；体检新增一项"当前内核与 NVIDIA 模块是否匹配" |
| **默认不碰 nouveau 之外的模块** | 只写自己的 `rc-drivers.conf`；不删发行版文件 |
