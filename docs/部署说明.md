# 部署说明（开发者视角）

面向「怎么把代码放上去跑」。面向终端用户的安装交互细节见 [install.md](install.md)。

## 先选一条路

| 场景 | 做法 | 耗时 | 会重启面板吗 |
|---|---|---|---|
| 新机器装面板 | `install.sh` 一行命令 | 3~5 分钟 | — |
| 升级已有面板（二进制 / 前端） | 面板内「面板更新」或重跑 `install.sh` | 1~2 分钟 | 是 |
| 只改插件 | 面板上传插件包，或直接放目录 | 10 秒 | 否（只重启插件进程） |

**关键区别：插件不在面板包里。** 发布资产 `raincough-linux-x86_64-<版本>.tar.gz` 只含
`raincough`(二进制) + `VERSION` + `install.sh` + `CHANGELOG.md` + `releases.json` + `public/`。
插件是 `plugins/` 下的独立目录，面板启动时扫描 `RC_PLUGINS_DIR`，与二进制解耦。

## 一、新机器：一行命令

```bash
# 跟随最新版
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/fongwuyan/RainCough-panel-web/main/install.sh | bash

# 钉死某个版本（tag 冻结，永久有效）
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/fongwuyan/RainCough-panel-web/v1.0.0-beta/install.sh | bash
```

脚本做五步：确认 → 环境检查（含 root 密码）→ 插件运行时（python/php/java/node/go 按需装）
→ 下载主体 → 安装 + 验证。

装完的结果是固定的：

| 项 | 值 |
|---|---|
| 安装目录 | `/opt/raincough` |
| 运行用户 | `root` |
| 端口 | 从 3900 起取第一个空闲（被自己占用则沿用） |
| systemd | `raincough.service`（`Restart=always`） |
| 数据 / 插件 / UDS | `/opt/raincough/data` · `/opt/raincough/plugins` · `/run/raincough` |
| 登录密码 | 首次启动随机生成，写进 `journalctl -u raincough` |

完全免交互（适合脚本化）：

```bash
curl -fsSL .../install.sh | RC_ROOT_PASSWORD='xxx' RC_ADMIN_PASSWORD='yyy' \
  RC_PLUGIN_LANGS=python RC_NET_STATIC=no bash
```

其余可用变量（`RC_PORT` / `RC_APP_DIR` / `RC_RUN_USER` / `RC_UNIT_NAME` / `RC_MIRROR`…）见 install.md。

## 二、升级已有面板（改过 Go 或 web/）

### 2.1 面板内更新（最省事，前提是该版本已发 Release）

右上角「面板更新」悬浮窗：检查 → 下载并应用 → 确认重启。三步都手动，不会静默升级。

### 2.2 从源码构建后手动替换

```bash
cd RainCough-Core

# ① 前端（只在改过 web/ 时才需要，产物进 public/）
cd web && npm run release && cd ..     # = check-undefined + check-bindings + vite build

# ② 交叉编译（Windows / macOS 都能出 linux 二进制）
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags "-s -w" -o dist/raincough ./cmd/raincough
```

上传并重启：

```bash
scp dist/raincough f@<host>:/tmp/raincough
ssh f@<host> 'sudo systemctl stop raincough && \
  sudo cp /opt/raincough/raincough /opt/raincough/raincough.bak-$(date +%Y%m%d-%H%M%S) && \
  sudo install -m 755 /tmp/raincough /opt/raincough/raincough && \
  sudo systemctl start raincough'
```

保留 `.bak-时间戳` 是硬习惯 —— 面板是管理入口，起不来就得靠备份回滚。

### 2.3 打正式发布包

```bash
tools/pack-release.sh            # 版本读 VERSION
tools/pack-release.sh 1.0.1      # 或显式指定
```

它按固定顺序做：前端 check+build → 交叉编译 → 组装 `dist-build/raincough-<版本>/` →
**强制文本文件 LF 行尾** → `bash -n` 语法自检 → 打 tar.gz → 校验包内 VERSION 与
install.sh 内嵌版本一致 → 回写 `releases.json`。

> 行尾那步不是洁癖：工作区被 `core.autocrlf` 转成 CRLF 后，`#!/usr/bin/env bash\r`
> 会让内核回退到 dash，`set -euo pipefail` 当场报「无效的选项名」，安装直接失败。
> 2026-10-18 实际踩过一次。

发版流程（tag / Release / 资产上传）见 [release.md](release.md)。

## 三、只更新插件

插件 = 一个目录：`plugin.json` + 后端入口 + `assets/plugin.js`（前端产物）。

### 3.1 前端产物要先构建

插件前端是独立打包的，跟面板 `public/` 无关：

```bash
node tools/build-plugin-frontend.js atk      # 产物 plugins/atk/assets/plugin.js
```

### 3.2 两种上法

**A. 面板上传（不用 ssh）**
「插件」页 → 上传，支持 `.zip` / `.tar.gz` / `.tgz` / `.tar`，面板负责解压、校验
`plugin.json`、注册到服务列表。上传入口在插件库解锁之后（口令是写死在二进制里的哈希，
忘了就只能走 B）。

```bash
# 打一个插件包
cd plugins && tar czf /tmp/atk.tar.gz atk
```

**B. 直接放目录（确定可用，不依赖口令）**

```bash
# 先落到 /tmp 再 sudo 解压 —— sudo 会吃掉管道里的 stdin, 不能直接 `| sudo tar`
cat /tmp/atk.tgz | ssh f@<host> '
  cat > /tmp/atk.tgz &&
  cd /opt/raincough/plugins && sudo tar xzf /tmp/atk.tgz && sudo chown -R root:root atk'
```

`--exclude='data'` 必须加 —— 插件的 sqlite 库和上传样本都在 `data/` 下，
覆盖上去等于把线上数据冲掉。

### 3.3 让新代码生效

插件进程由面板 supervisor 托管，**杀掉就自动拉起**：

```bash
pkill -f 'plugins/atk/server_v4'      # 3 秒后新进程带新代码起来
```

不需要重启面板。改的是插件前端（`assets/plugin.js`）时更简单 —— 静态文件，
浏览器强刷即可。

### 3.4 部署后自检

```bash
# 1) 接口注册数对不对（改了接口最容易漏 plugin.json）
grep -c '"id": "atk\.' /opt/raincough/plugins/atk/plugin.json
python3 -c "import json;print(json.load(open('/opt/raincough/plugins/atk/plugin.json'))['version'])"

# 2) 进程在不在
ps -ef | grep '[a]tk/server_v4'

# 3) 接口能调（先登录拿 cookie）
curl -s -c ck.txt -X POST -H 'Content-Type: application/json' \
  -d '{"password":"<面板密码>"}' http://<host>:3900/api/auth/login
curl -s -b ck.txt -X POST -H 'Content-Type: application/json' \
  --data-binary '{"params":{}}' \
  http://<host>:3900/api/interfaces/atk.env.info/invoke
```

> 调接口两个坑：body 必须是 `{"params":{...},"timeout_ms":N}`（直接传参数对象会被当成空
> params）；Windows 下 curl 的 `-d` 会被 cmd 吃掉双引号，要改用 `--data-binary @-` 走 stdin。

## 四、这台机器的实际配置

`192.168.2.200` 上跑着两个实例，用途分开：

| | 生产 | 开发 |
|---|---|---|
| 端口 | **3900** | **3910** |
| systemd | `raincough.service` | `rc-v6.service` |
| 目录 | `/opt/raincough` | `/home/f/raincough-v6` |
| 用户 | root | f |
| 来源 | GitHub Release（install.sh 装的） | 从源码构建 |
| 版本 | 1.0.0-beta | 跟随开发 |

**约定：新功能先在 3910 验证，再发版上 3900。** 两个单元的注释里也写着这句。

改插件时的实际做法（两个都更新）：

```bash
cd RainCough-Core/plugins
tar czf /tmp/atk.tgz --exclude='data' --exclude='__pycache__' atk
cat /tmp/atk.tgz | ssh f@192.168.2.200 '
  cat > /tmp/atk.tgz &&
  cd /home/f/raincough-v6/plugins && tar xzf /tmp/atk.tgz && echo V6_OK &&
  sudo tar xzf /tmp/atk.tgz -C /opt/raincough/plugins && echo V9_OK &&
  sudo chown -R root:root /opt/raincough/plugins/atk && rm -f /tmp/atk.tgz'
```

## 五、常见问题

**装完打不开 / 端口不对**
`systemctl status raincough` 看是否 active；端口写在 `ExecStart=... -port N`，
实际端口以 `systemctl cat raincough` 为准，不要假设一定是 3900。

**面板起来了但插件是灰的**
插件后端没注册上。看 `journalctl -u raincough | grep <插件名>`，常见原因：`plugin.json`
语法错、`backend.exec` 指向的文件不存在、Python 解释器缺失（`RC_PLUGIN_LANGS` 没装）。

**插件改了不生效**
八成是只改了 `frontend/plugin.js` 没跑 `build-plugin-frontend.js` ——
面板加载的是 `assets/plugin.js`，不是源文件。

**升级后白屏**
前端产物没更新。`public/` 必须跟着二进制一起换（`pack-release.sh` 会自动带上）。
浏览器强刷一次排除缓存。

**要卸载**
`bash /opt/raincough/uninstall.sh`，或用 `docs/install.md` 里的方式。
