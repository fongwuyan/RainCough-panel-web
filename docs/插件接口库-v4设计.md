# RainCough 插件接口库 v4 设计（已实现定稿）

> 状态: **M0–M5 全部完成并上线**(2026-09): 17/17 插件 v4、拆 v3、70 个 `system.*` 接口。
> 范围: 插件自注册、无端口、Vue3 前端驻主系统、后端独立任意语言、接口库为安装时注册的服务总线。
> 兼容: v3 PluginHost/网关已删除(internal/host 移除)。

---

## 0. 设计约束（用户确认）

1. 插件**完全独立**（不依赖主系统任何内部代码）。
2. 插件**不占用端口**（无 TCP/UDP 监听；生产 UDS，Windows 开发机允许 loopback TCP 降级）。
3. 插件**没有独立网页**，内容页**只能**在主系统内显示。
4. 前端**必须 Vue3**，且**前端产物存主系统**、由主系统渲染。
5. 后端**语言任意**、**独立进程**，并**集结全部处理逻辑**。
6. **共用接口库**：安装插件时**注册接口**，接口可被**其他插件调用**。
7. 主系统职责收敛：**界面显示 + 健康诊断**；系统功能保留并逐步接口化。
8. 新增系统选项卡「接口总览」；插件健康页重做为「服务健康中心」。

## 1. 总体架构（三层分离）

```
┌─ 主系统 RainCough Core ──────────────────────────────────────┐
│ 展示壳(Vue3, 纯渲染): /plugin/<name>/<page>                    │
│ 接口库(Service Bus): 注册/路由/权限/版本/统计                    │
│ 后端接入: 传输层(UDS/TCP) + 健康诊断                            │
│ 系统功能(内置 Provider): 文件/终端/媒体/任务/调度/环境包/系统中心  │
└──────┬─────────────────────┬──────────────────────┬───────────┘
       │ UDS 注册/心跳/invoke   │ 经接口库调用其他插件   │ 前端产物入主系统
┌──────▼─────────┐   ┌────────▼────────┐   ┌─────────▼─────────┐
│ 插件A 后端(任意) │   │ 接口注册表       │   │ 插件A Vue3 前端     │
│ 全部处理逻辑     │   │ core_ifaces     │◄──┼ ctx.invoke(...)    │
└────────────────┘   └─────────────────┘   └────────────────────┘
```

| 层 | 拥有 | 禁止 |
|---|---|---|
| Vue3 前端 | 界面渲染、交互状态 | 业务计算、直连后端、文件/存储访问 |
| 接口库 | 接口注册/路由/权限/版本/统计 | 任何业务逻辑 |
| 插件后端 | 一切处理逻辑、数据、外部 API | 依赖主系统内部模块；监听端口 |

## 2. 插件清单 plugin.json v4

```json
{
  "name": "uptime",
  "label": "Uptime 监控",
  "version": "3.0.0",
  "description": "...",
  "icon": "/assets/icon.png",
  "frontend": {
    "entry": "assets/plugin.js",
    "pages": [ {"path": "", "title": "概览"}, {"path": "history", "title": "历史"} ],
    "vue": "3.5"
  },
  "backend": {
    "lang": "python",
    "exec": ["python3", "server.py"],
    "capabilities": ["invoke", "heartbeat", "log.tail"]
  },
  "interfaces": [
    { "id": "uptime.targets.list",
      "input":  {"type":"object","props":{"page":{"type":"integer"}}},
      "output": {"type":"object","props":{"targets":{"type":"array"}}},
      "visibility": "all",
      "version": "1" }
  ]
}
```

校验规则: name 唯一(`^[a-zA-Z0-9_-]{1,32}$`, 允许大写如 JMComic)、frontend.entry 必填、interfaces 可为空数组、接口 id 全局唯一(`<插件名>.<方法>`)。

## 3. 接口库生命周期

| 时机 | 动作 | 状态 |
|---|---|---|
| 安装插件 | 校验 plugin.json → 前端产物入主系统 `public/plugins/<name>/` → 接口登记 `core_ifaces` | registered |
| 后端启动 | 连接(传输层) → `register`(声明实现接口+绑定) → 心跳 | bound/online |
| 后端离线 | 探针失败/超 lease | offline(调用返回 43xx) |
| 卸载插件 | 注销接口 + 删前端产物(提示停后端) | removed |

注册表记录(ns `core_registry`, KV 持久化):
```jsonc
{
  "name": "uptime", "version": "3.0.0",
  "manifest": {...}, "frontend": {...}, "backend": {...},
  "registered_at": ..., "last_seen": ...,
  "binding": null,          // {transport, endpoint}
  "status": "registered|online|offline|expired",
  "latency_ms": 12, "fail_count": 0
}
```

接口记录(ns `core_ifaces`):
```jsonc
{
  "id": "uptime.targets.list", "plugin": "uptime",
  "visibility": "all", "iface_version": "1",
  "input_schema": {...}, "output_schema": {...},
  "binding_online": true,
  "stats": {"calls": 0, "avg_ms": 0, "p95_ms": 0, "last_error": null}
}
```

## 4. 传输与 RPC（JSON-RPC 2.0）

- 生产: Unix Domain Socket, 主系统监听 `/run/raincough/plugins/<name>.sock`(目录 0700), 插件主动连接。
- 开发(Windows): 环境 `RC_PLUGIN_TRANSPORT=tcp` 走 127.0.0.1 临时端口(不用于生产)。
- 断线指数重连(1s→30s 封顶); 主系统重启后插件自动重连并重注册。

| 方法 | 方向 | 用途 |
|---|---|---|
| register | 插件→主系统 | 名片+接口绑定+页面清单 |
| heartbeat | 插件→主系统 | 保活(默认 30s) |
| unregister | 插件→主系统 | 正常下线 |
| ping | 主系统→插件 | 健康探针 |
| invoke | 主系统→插件 | 执行业务 |
| log.tail | 主系统→插件 | 诊断日志(可选能力) |

错误码(实测): `-32601` 插件请求超时(主系统 invoke 默认 15s, 可传 timeout_ms) / `-32603` 内部;
`3000` 业务错误(`rc.RCError(3000, msg)`); `4001` 接口未注册; `4101` 参数校验失败; `4201` 无权限;
`4301` 目标离线; `4401` 接口版本不匹配。

可见性: `all`(主系统 UI + 任意插件) | `main`(仅主系统 UI) | `private`(仅本插件)。

## 5. 前端契约（Vue3, 纯展示, 存主系统）

- 产物: 单文件 `plugin.js`(构建时 vue external, 运行时主系统壳注入)。
- 存储/渲染: 安装时入 `public/plugins/<name>/assets/plugin.js`; 主系统 `/plugin/<name>/<page>` 壳内渲染。
- 入口:
```js
import { definePlugin } from '@raincough/plugin-vue'
export default definePlugin({
  pages: [{ path: '', title: '概览' }],
  setup(ctx) { const list = await ctx.invoke('uptime.targets.list', {}) }
})
```
- ctx: `{ plugin, invoke(iface,params,opts), on(event,cb), emit(event,payload), toast(msg,kind), navigate(to) }`
- 纯展示保证: 构建期 lint 禁止 frontend 内 `fetch`/`WebSocket`/后端地址(实现于 SDK 工具)。

## 6. 后端契约（任意语言）

- 传输: UDS(生产)/TCP(开发)。
- SDK 职责: 连接/重连、register/heartbeat/unregister 自动执行、接口路由表(`@rpc("id")`)、跨插件调用 `sdk.call(iface,params)`、统一日志 `.runtime.log`。
- 唯一依赖 = 接口库 SDK; 进程外部管理(systemd Restart=always); 数据留在插件目录。

## 7. 主系统改造（增量, 旧代码保留）

```
internal/pluginx/
├─ pluginx.go      # 入口/选项/生命周期
├─ conn.go         # 单连接 JSON-RPC 读写循环(读循环 + go 每请求 worker)
├─ registry.go     # 注册表(core_registry) + 接口目录 + RegisterSystemProvider + 路由
├─ prober.go       # 健康探针(ping/心跳/状态机)
└─ http.go         # HTTP 端点(ServeAsset/ServePluginFile/ListPlugins)
```
新增 API:
```
GET  /api/interfaces?source=&visibility=&status=&q=&page=   目录+统计
GET  /api/interfaces/<id>                                   详情(schema/绑定/统计)
POST /api/interfaces/<id>/invoke                            试调用
GET  /api/interfaces/stats/summary                          汇总卡
GET  /api/services/health                                   服务健康中心数据(注册表驱动)
POST /api/plugins/<name>/invoke                             前端 invoke 桥
```
前端: `PluginShell.vue` + `/plugin/:name/:page` 路由 + `Ifaces.vue`(接口总览) + 侧栏选项卡 + 插件健康页改注册表驱动。

## 8. 「接口总览」系统选项卡

- 入口: 侧栏系统区新增「接口总览」(`/ifaces`)。
- 页面: 汇总行(总数/系统/插件/离线) + 接口表格(按插件分组) + 详情面板(schema/绑定/统计/调用关系/试调用)。
- 数据: 上述 `/api/interfaces*` 端点。

## 9. 服务健康中心（插件健康重做）

- 数据源: 接口库注册表 + 探针(不再依赖 PluginHost 子进程状态)。
- 展示: 全部 Provider(内置系统 + 插件)同一表格: 名称/类型/版本/状态/接口数/延迟/心跳/错误 + 展开接口列表 + 日志入口。
- 处置: 只诊断不治疗, 离线提示检查插件 systemd。

## 11. 验收标准（本地）

1. demo 插件: 启动后端 → 注册 → 接口目录可见 → invoke 往返 → 杀进程 → 离线 → 重启 → 恢复。
2. 插件无端口(生产 UDS)、无独立网页; 接口总览可筛选/详情/试调用。
3. go vet/build/test 全绿; 旧功能与旧插件机制不受影响。
