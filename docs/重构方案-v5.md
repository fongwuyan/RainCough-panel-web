# RainCough 重构方案（v5）

> ⚠ **已被 `重构方案-v6.md` 取代**。v5 里的 PHP 业务层方案作废（PHP 解释器本身违反零依赖目标）。
> 保留此文档仅为记录当时的取舍过程。现行方案见 v6。

> 决策日期：2026-10-17
> 目标栈：**Vue 3 + PHP + Go**（Python 退出）
> 保留范围：**工作台 / 文件管理 / 终端 / 插件 / 设置 / 常驻浮窗（面板更新）**，其余系统功能全部移除。
> 插件：**只保留机制，17 个业务插件全部移除**。

---

## 1. 职责边界

```
浏览器
  │  HTTP :3900（nginx 静态托管 public/ + PHP-FPM）
  ▼
PHP 业务层  ── 会话鉴权 · 插件市场编排 · 设置 · 面板更新编排
  │  /api/sys/* → 127.0.0.1:3901（回环 + X-RC-Token）
  ▼
Go 系统服务  rc-core.service :3901（不对外）
  ├─ 文件 /api/fm/*        终端 /api/terminal/*
  ├─ 监控 /api/system /api/disks /api/workspace/history
  ├─ 插件运行时监督 pluginx（systemd 单元 · UDS · 心跳 · invoke · assets）
  └─ 二进制自替换 + 重启（面板更新唯一必须留在 Go 的动作）
        │ UDS 行分隔 JSON-RPC 2.0
        ▼
插件进程  plugin-<name>.service（PHP CLI + rcplugin.php）
```

**分工原则**：PHP 处理"用户要什么"（清单、下载、校验、状态、编排），Go 处理"机器怎么动"（文件、终端、进程、权限、systemd、自替换）。

**关键取舍：URL 保持不变。** PHP 在前置路由里按路径分流 —— `/api/fm/* /api/terminal/* /api/system /api/disks /api/workspace/* /api/plugins/*/invoke` 转 Go，其余走 PHP。这样前端 `api.js` 的 149 个方法几乎不用改，重构风险集中在一层。

## 4. 插件机制改造（v5 契约）

协议不变，只换运行时语言 —— Go 侧 `pluginx` 零改动：

| 项 | v4 | v5 |
|---|---|---|
| 后端语言 | Python（`server_v4.py`） | PHP（`server.php`） |
| SDK | `rcplugin.py` | `rcplugin.php`（UDS 行分隔 JSON-RPC 2.0，同协议） |
| 单元 | `plugin-<name>.service` exec python | exec `php server.php`，其余不变 |
| 清单 | `backend.lang: "python"` | `backend.lang: "php"` |
| 依赖 | `requirements` → pip / envpkg | `composer.json`（可选，面板不代装） |

顺带删掉 `envpkg`（Python 虚拟环境管理）——PHP 不再需要离线 wheel 与 venv 体系，安装器少 411MB 资产。

## 5. 实施阶段

**P0 清场（0.5 天，可回滚）**
删上表代码与路由 → `go build` 通过 → 前端 `vite build` 通过 → 冒烟：5 个页面 + 浮窗全可用，控制台无 404。
*验收：`grep -r sysfunc web/src cmd` 为空；路由数从 122 降到 ~40。*

**P1 PHP 骨架（1–2 天）**
`web-php/` 新建：路由分发（按前缀转 Go / 自处理）、`X-RC-Token` 回环调用、静态托管交给 nginx。
先接管三件事：`/api/store/*`、`/api/panel/*`（除自替换）、`/api/settings`。
*验收：关掉 Go 的这三组路由后，插件页与浮窗行为不变。*

**P2 拆 Go（2–3 天）**
`main.go` 只留路由注册与启动；handler 从 `cmd/` 移到 `internal/httpapi/`，业务落 `internal/core`；`pluginx` 保持独立包。
*验收：`cmd/raincough` 单文件 < 200 行；`internal/httpapi` 按域分文件。*

**P3 插件运行时换 PHP（1–2 天）**
写 `rcplugin.php` + 一个最小示例插件（echo + 1 个接口），走完 安装 → 启动 → 注册 → invoke → 卸载 全链路。
*验收：示例插件在 `.234` 测试机跑通，Go 侧代码无改动。*

**P4 安装器与发布（1 天）**
`install.sh` 增加 nginx + php-fpm + 目录权限；`raincough.service` 改名 `rc-core.service` 且只监听回环；资产包去掉 env-offline。
*验收：全新 Ubuntu 22.04 一条命令装完，5 页可用。*

## 6. 风险与待决

1. **权限模型**：PHP 以 `www-data` 运行，Go 以 `f`/root 运行。所有需要 root 的动作必须留在 Go，PHP 不得直接 sudo。
2. **面板更新自替换**：Go 替换自己的二进制并重启，这是唯一无法迁到 PHP 的动作。PHP 负责下载/校验/写状态，Go 负责 swap + restart + 回滚。
3. **鉴权仍是空白**：全站 `StatusUnauthorized` 零命中。既然 PHP 接管业务层，建议在 P1 一并做（会话 + 单管理员口令），否则 PHP 层会复制同样的洞。
4. **功能面收窄的后果**：删掉系统中心后，面板从"运维面板"退化为"文件 + 终端 + 监控"三件套；drivers 扩展与 `.143` 矿卡魔改工作一并作废。已确认。
5. **市场空窗**：17 个插件下线后，插件页只有机制没有内容，需要先有一个 PHP 示例插件撑住市场链路。
