# RainCough 架构总览

> 版本: v4(接口库时代)。v3 PluginHost(端口+网关)已于 M5 拆除。

## 1. 进程模型

```
┌─ 主系统 raincough (Go, 单二进制, :3900) ─────────────────────────────┐
│  HTTP API + 静态前端(public/)          internal/pluginx 接口库       │
│  系统功能 Provider(system.*, 70 接口)   注册表/路由/prober/http        │
└──────────────┬───────────────┬──────────────────┬───────────────────┘
               │ UDS 注册/心跳/invoke   │ 自带 systemd 管理     │ 前端产物托管
        ┌──────▼───────┐   ┌───────────▼──────────┐   ┌──────────▼────────┐
        │ plugin-<name> │   │ plugin-<name2>.service│  │ /api/plugins/     │
        │ (systemd 单元, │   │ (同上, 无端口)        │  │ <name>/invoke     │
        │ Python 进程)   │   └──────────────────────┘  │ assets|cache|output│
        └──────────────┘                               │ |work 文件服务     │
                                                       └───────────────────┘
```

- 每插件 = 独立 systemd 单元 `plugin-<name>.service`(User=f, Restart=always), **无任何 TCP 端口**。
- 插件后端 = `plugins/<name>/server_v4.py`(Python, import 旧 `server.py` 复用逻辑) + SDK `rcplugin.py`。
- 主系统通过 Unix Domain Socket `/run/raincough/plugins/<name>.sock` 与插件通信(开发机 Windows 用 TCP 降级)。

## 2. 三套契约

| 契约 | 说明 | 文档 |
|---|---|---|
| plugin.json v4 | 清单(frontend/backend/interfaces) | 插件开发指南 |
| RPC(JSON-RPC 2.0, 行分隔) | register/heartbeat/unregister/ping/invoke/log.tail | 接口库设计 |
| 前端 ctx | `ctx.invoke(iface, params)` 唯一业务入口 | 前端开发指南/插件开发指南 |

## 4. 数据流

- **插件页**: 浏览器 → 主系统 `/plugin/<name>` → PluginView 加载 `assets/plugin.js` → `ctx.invoke` → `POST /api/plugins/<name>/invoke` → pluginx 路由 → UDS RPC `invoke` → 插件 handler → 结果回传。
- **跨插件/系统接口**: 任意插件前端也可 `ctx.invoke('system.*' 或 'other.plugin.*')`, 由 pluginx 统一路由(可见性 all/main 控制)。
- **文件产物**: 插件写 `cache/ output/ work/` 子目录, 主系统经 `/api/plugins/<name>/<sub>/<file>` 代发下载/预览。

## 5. 健康与诊断

- 插件在线 = 注册 + 心跳(30s), 主系统探针 ping 测量延迟, 超出 deadline 标 offline。
- 「服务健康中心」(注册表驱动) = 唯一健康视图; 展开行看接口与日志(`/api/services/health/log`)。
- 自愈: systemd Restart=always + SDK 指数重连(1s→30s), 主系统重启后插件自动重连重注册。

## 6. 数据层

- 单 sqlite(`data/rc.db`), `shared.Namespace` 提供 KV 表(`ns_<ns>_kv`)。
- `core_registry` 持久化注册表(196 行); 各插件/系统模块各自 namespace。
- 默认 DSN `sqlite:///rc.db`(相对 DataDir → `data/rc.db`)。
