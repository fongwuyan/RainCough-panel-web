## 四、部署流程(标准, 必须完整执行)

宿主机脚本模式(每个脚本先 scp 到 /tmp 再 bash 执行, 禁止内联引号):

```bash
# /tmp/deploy_standard.sh (完整流程, 缺一不可)
cd ~/raincough-dev
export PATH=$HOME/go-tool/go/bin:$PATH
tar -xf src.tar 2>/dev/null && rm -f src.tar          # 1. 解压(必须是最新 git archive)
go build -o raincough ./cmd/raincough                  # 2. Go 编译
cd web && node node_modules/vite/bin/vite.js build     # 3. 前端构建 → 输出到 ../public (=~/raincough-dev/public, 即 Go 服务目录!)
cd ..
kill 旧进程 && nohup ./raincough -port 3900 > srv.log 2>&1 &   # 4. 重启
```

**关键认知(教训来源)**:
- vite.config.js `outDir: '../public'` → 从 `web/` 构建时**输出到 `~/raincough-dev/public`**(不是 web/public)
- Go 二进制静态目录 = **`BaseDir/public`** = `~/raincough-dev/public`
- **构建产物校验**: `curl -s :3900/` 引用的 JS 必须 **>1MB**(复用版 1.48MB); <300KB = 简化版, 部署失败
  ```bash
  JS=$(curl -s http://127.0.0.1:3900/ | grep -oE 'assets/index-[^"]+\.js' | head -1)
  curl -s -o /dev/null -w "%{size_download}\n" "http://127.0.0.1:3900/$JS"   # 应≈1552338
  ```

## 六、Git 历史要点

- 仓库用 `git archive --format=tar HEAD -o testdata/src.tar` 打包(工作目录必须 `E:\jiaob\RainCough-Core`)
- 新写的 .go/.vue 文件**务必 `git add -f`**(曾多次因未跟踪导致部署旧代码)
- **禁用 PowerShell `Set-Content` 写含中文文件**(GBK 编码损坏, 一律用 write/edit 工具)
- 远程命令用脚本文件(scp → bash /tmp/x.sh), 禁止内联双引号
