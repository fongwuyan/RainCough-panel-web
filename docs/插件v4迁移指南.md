# 存量插件 v4 迁移指南（M5）

> 目标: 17 个 Python 插件从"端口 + HTTP 网关"迁到"无端口 + 接口库自注册"。
> 原则: 业务逻辑全部留在插件后端; Vue3 前端产物存主系统; 主系统只做接口路由与健康诊断。

## 1. 一键生成骨架

```bash
python tools/migrate-plugin-v4.py plugins/uptime -o v4-out/uptime
```

输出：`plugin.json`(v4) + `server_v4.py`(接口 handler 占位) + `rcplugin.py`(SDK)
     + `plugin-<name>.service`(systemd) + `MIGRATE.md`(该插件步骤)。

## 2. 迁移顺序（推荐）

1. **P0 样板**: uptime（已有 Vue3 前端，作全链路验证）
2. **P1 高频**: aigen / mcserver / docker / laizhangsetu / vpn / kvm
3. **P2 工具类**: compress / dltool / filehash / imagetool / ocrqr / texttool / webspy / mcskin / touchgal / JMComic

## 3. 插件侧改造（每个插件）

| 项 | 动作 |
|---|---|
| 后端 | 把 v3 `server.py` 各路由逻辑移入 `server_v4.py` 对应接口 handler（`@rc.interface("插件.方法")`）|
| 数据 | 继续使用插件自身 `data/`（接口库不接管数据）|
| 前端 | `frontend/plugin.js` 按 @raincough/plugin-vue 契约（`RegisterGlobal(name, {pages, mount})`），`node tools/build-plugin-frontend.js <name>` 构建产物入主系统 |
| systemd | 独立单元，`Restart=always`，无端口（SDK 读主系统预写的 `.rc.endpoint`）|
| 依赖 | 仅 `rcplugin.py`（复制进插件目录或用共享 SDK 路径）|

## 4. 主系统侧（已完成）
- `internal/pluginx`：UDS/TCP 传输、注册表、接口目录、健康、invoke（M2，已合入）
- 服务健康中心 / 接口总览（M3，已合入）
- 系统功能接口化 `system.*`（M4，已合入）

## 5. 验收（每插件）
1. 杀插件进程 → 服务健康中心变灰；systemd 自动拉起 → 自动重连恢复。
2. 「接口总览」出现该插件接口，试调用成功。
3. 旧 `/api/plugins/<name>/*` 网关停止使用；浏览器无插件独立入口（只有主系统页面）。

## 6. 拆除 v3（最后一步，仅在全部插件迁完后执行）
- 删除 `internal/host` 拉起/网关、`PluginView` v3 分支、`/api/sys/plugins-health` 兼容数据源；
- 存量 `plugins/*` 目录内的 v3 `server.py` 归档删除；回归 + 部署。
