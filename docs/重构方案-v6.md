# RainCough 重构方案（v6 · 零依赖单二进制）

> 决策日期：2026-10-17（取代 v5）
> **技术栈：Vue 3（构建期）+ Go 标准库（运行期）**
> **PHP 取消** —— PHP 解释器本身就是系统环境依赖，与"零依赖"目标冲突。
> **依赖红线：Go 侧只允许标准库，`go.mod` 的 require 段清空；运行期不 exec 任何外部命令。**
> 保留功能：工作台 / 文件管理 / 终端 / 插件 / 设置 / 常驻浮窗。

---

## 1. 目标形态

```
raincough          15–20MB 静态 ELF（CGO_ENABLED=0）
  ├─ 内嵌 public/  前端产物（embed.FS，单文件分发）
  ├─ HTTP :3900    标准库 net/http
  ├─ 存储          data/kv/*.log  自研 append-only KV
  ├─ 监控          读 /proc /sys + syscall.Statfs
  ├─ 终端          syscall 手写 PTY（/dev/ptmx + ioctl）
  └─ 插件          fork/exec 子进程 + UDS JSON-RPC（自管，不用 systemd）
```

分发 = 一个二进制 + 一个 `data/` 目录。宿主机不需要 Python、PHP、nginx、sqlite、systemd 单元、任何 apt 包。

## 2. 依赖清零对照

| 现状 | 类型 | 替代 |
|---|---|---|
| `github.com/creack/pty` | Go 包 | `syscall` 手写 PTY ≈120 行：`open(/dev/ptmx)` → `ioctl(TIOCSPTLCK,0)` → `ioctl(TIOCGPTN)` → 子进程 `setsid`+`TIOCSCTTY`+`dup2`+`exec`；改窗口大小 = `ioctl(TIOCSWINSZ)` |
| `modernc.org/sqlite` | Go 包 | 自研 KV（见 §4），`shared.Namespace` 接口保持不变 |
| `github.com/go-sql-driver/mysql` | Go 包 | 直接删除（面板本身无 MySQL 需求） |
| `systemctl` ×9 | 外部命令 | Go 内建 supervisor：`exec.Command` + 进程组 + 指数退避重启 + 日志轮转 |
| `df` `free` `lsblk` `ip` | 外部命令 | `/proc/self/mounts` `/proc/meminfo` `/proc/partitions` `/proc/net/dev` + `syscall.Statfs` |
| `nvidia-smi` `lspci` | 外部命令 | `/proc/driver/nvidia/gpus/*/information` + `/sys/bus/pci/devices/*` |
| `7z` `rar` `xz` `zst` `lz4` | 外部命令 | 只保留 `zip`(archive/zip) `tar`(archive/tar) `gz` `bz2`(compress/*)，其余格式下线 |
| `python3` `pip` | 运行时 | 已随插件删除一并移除 |
| `ffmpeg` `tar`(命令) | 外部命令 | 媒体处理与备份功能已删，无替代需求 |

`go.mod` 目标：只有 `module` 与 `go` 两行，`require` 段为空。

## 3. 能力收缩（必须知情）

1. **GPU 卡片降级**：无 `nvidia-smi` 就拿不到利用率/温度/显存占用，只剩型号、驱动版本、PCI 地址。要么接受降级，要么整卡删掉。
2. **解压格式收缩**：`.7z .rar .xz .zst .lz4 .lzma .iso` 不再支持，只认 `zip/tar/gz/tgz/bz2`。
3. **终端仅 Linux**：PTY 走 Linux ioctl，Windows 开发机跑不起来（本来也只部署 Linux）。
4. **面板自身启动**：程序运行期不调 `systemctl`，但开机自启仍需宿主机某种机制。安装器策略：有 systemd 就写单元，没有就 `nohup` + pid 文件 —— 这是唯一保留的外部约定，属于"安装"而非"运行"。
5. **进程自管的风险**：原来 systemd 负责 `Restart=always`、日志、cgroup 限制；改自管后这些要自己实现，插件进程崩溃恢复、僵尸回收、资源限制全部由 Go 承担。

## 4. 数据层（自研 KV）

保持 `shared.Namespace` 的方法签名不变，底层换实现：

```
data/kv/<ns>.log     追加写：每行 {"k":"...","v":<json>,"t":1700000000}
data/kv/<ns>.snap    定期快照（回放超过 N 行或启动时）
```

- 写：`O_APPEND` 追加 + `fsync`（可配置 `--fsync=always|interval|never`）
- 读：启动时 snap + 回放 log → 内存 map；读走内存
- 删：写一条 `{"k":"...","d":true}` 墓碑，compact 时清除
- 并发：单写锁（`sync.Mutex`）+ 读无锁（`atomic.Value` 换 map）
- 崩溃恢复：log 尾部半行丢弃即可（行分隔 + 单行完整性校验）

规模评估：当前 `store.go` 659 行 + `shared/{db,kv,ns}.go` 396 行，接口稳定，替换集中在这 396 行。

## 5. 插件机制 v6

插件不再需要解释器 —— 每个插件是一个**静态 Go 二进制**：

```
plugins/<name>/
  plugin.json      { backend: { lang: "go", exec: ["bin/server"] }, interfaces: [...] }
  bin/server       静态编译产物（按 arch 分发）
  assets/plugin.js 前端产物（宿主 Vue 运行时挂载）
```

- 协议不变：UDS 行分隔 JSON-RPC 2.0（register/heartbeat/invoke/log.tail），Go 侧 `pluginx` 零改动
- supervisor：`fork/exec` → 子进程组 → UDS 连接 → 心跳超时判死 → 指数退避重启（1s→30s）
- 17 个业务插件已全删，只留机制 + 一个示例插件验证链路

## 6. 阶段

**P0 清场**（沿用 v5 删除清单，去掉 PHP 相关）
删 ext/media/sysfunc/scheduler/store/envpkg/backup/apimon 等 4,361 行 Go + 80 条路由 + 30 个前端目录 + 17 个插件。产出：能编译、5 页可用。

**P1 存储替换**（1 天）
`shared/db.go` 换成文件 KV，`go.mod` 去掉 sqlite/mysql。验收：`data/rc.db` → `data/kv/*.log`，重启后设置/插件状态不丢。

**P2 PTY 手写**（1 天）
`core/term.go` 换 syscall 实现，去掉 creack/pty。验收：终端开/输/改大小/关全通，`vim` 正常。

**P3 外部命令清零**（1.5 天）
监控改 `/proc`+`/sys`；`df/free/lsblk/ip` 全删；GPU 降级或删除；解压格式收缩；插件 supervisor 替代 systemctl。验收：`strace -f -e execve` 下除自身外无 exec。

**P4 单文件分发**（0.5 天）
`embed.FS` 内嵌 `public/`，`go build` 产物直接可跑；安装器改为"拷二进制 + 建 data 目录"。

**P5 插件示例**（1 天）
Go 示例插件跑通 安装→启动→注册→invoke→卸载。

## 7. 风险

1. **这不是重构，是重写核心四块**（存储 / PTY / 监控 / 进程管理）。P1–P3 每块都动到"面板能不能用"的根基，必须一块一验，不能并行。
2. **PTY 手写是唯一有难度的部分**：`TIOCSCTTY` 时序、`setsid` 与进程组、SIGWINCH 转发，任何一处错都表现为"终端卡住"。建议先写独立 demo 在 `.234` 上验证，再替换。
3. **自研 KV 的持久性**：没有事务、没有 WAL，断电可能丢最后几秒写入。若不可接受，需在 P1 加 fsync 策略或双写。
4. **能力收缩会影响使用习惯**：GPU 无温度/利用率、7z 不能解、Windows 不能开发调试。这三条要么接受，要么放弃"零依赖"。
5. **前端第三方库**：`xterm` `novnc` `skinview3d` 属构建期打包，运行期无外链，不计入依赖红线。若也要清零，需用现成的自研 `terminal/vt100.js` 替换 xterm（工作量大且渲染质量会降）。
