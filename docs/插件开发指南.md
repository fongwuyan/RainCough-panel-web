# 插件开发指南(v4)

> 面向新插件作者。做完本指南 = 一个可在主系统「插件页 + 接口总览」中使用的 v4 插件。

## 0. 一键骨架

```bash
python tools/migrate-plugin-v4.py plugins/<name> -o v4-out/<name>
```

输出 `plugin.json`(v4) + `server_v4.py` 占位 + `rcplugin.py` + systemd 单元 + `MIGRATE.md`。
已有 v3 `server.py` 的老插件 = 保留它, 在 `server_v4.py` 里 `import server as M` 复用逻辑。

## 1. plugin.json v4

```jsonc
{
  "name": "uptime",                    // 全局唯一(实际允许字母/数字/_/-, 见校验器)
  "label": "Uptime 监控",
  "version": "2.0.0",
  "description": "...",
  "icon": "",
  "frontend": {
    "entry": "assets/plugin.js",       // 主系统托管的前端入口
    "vue": "3.5",
    "pages": [{"path": "", "title": "概览"}]   // path 留空=单页
  },
  "backend": {
    "lang": "python",
    "exec": ["python", "server_v4.py"], // exec 第一元素固定 python/server_v4.py 命名
    "capabilities": ["invoke", "heartbeat", "log.tail"]
  },
  "interfaces": [
    {"id": "uptime.targets.list", "visibility": "all", "version": "1", "description": "列表"}
    // visibility: all=主系统UI+任意插件 | main=仅主系统UI | private=仅本插件
  ]
}
```

校验: `python interface/tools/validate_manifest.py plugins/<name>/plugin.json`。
注意: 校验器 NAME_RE 为 `^[a-zA-Z0-9_-]{1,32}$`(允许大写, 兼容 JMComic)。

## 2. 后端 server_v4.py(Python) / 任意语言

```python
import os, sys
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
import rcplugin as rc
import server as M            # 复用 v3 业务(若无则直接写)

@rc.interface("uptime.targets.list")          # 接口 id = 插件名.方法
def list_targets(params):
    return {"targets": [...]}                  # 返回 JSON 可序列化值

@rc.interface("uptime.targets.create")
def create_target(params):
    if not (params or {}).get("url"):
        raise rc.RCError(3000, "url 必填")     # 业务错误 rc.RCError(3000, msg)
    ...

if __name__ == "__main__":
    rc.serve(
        endpoint=os.environ.get("RC_ENDPOINT", ""),   # 主系统预写 .rc.endpoint, 或 env
        name="uptime",
        version="2.0.0",
        manifest={"label": "Uptime", "description": "..."},        # 显示用
        frontend={"pages": [{"path": "", "title": "概览"}]},       # 注册时上报
        iface_ids=["uptime.targets.list", ...],                    # 声明实现(应与 plugin.json 一致)
        plugin_dir=os.path.dirname(os.path.abspath(__file__)),
    )
```

要点:
- SDK 职责: 读 `.rc.endpoint` → 连接 UDS/TCP → register/heartbeat/unregister 自动 → 后台读循环 + 每请求 worker 协程(避免嵌套 `rc.call` 死锁)。
- 跨插件调用: `rc.call("other.iface.id", params)`(需要目标 visibility 允许)。
- 文件输入契约: 前端上传一律 base64 data URL; 文件产物写 `cache/ output/ work/`, 由主系统代发下载。

## 3. 前端 frontend/plugin.js(Vue3, 存主系统)

```js
import { createApp, h } from 'vue'
const NAME = 'uptime'
function mount(container, ctx) {
  const App = {
    data() { return { list: [] } },
    async mounted() {
      this.list = (await ctx.invoke('uptime.targets.list')).targets || []
    },
    render() {
      return h('div', null, [ h('div', {class:'section-title'}, 'Uptime'),
        this.list.map(t => h('div', null, t.name)) ])
    },
  }
  const vm = createApp(App); vm.mount(container)
  return () => vm.unmount()          // 卸载清理
}
export function register(g) {        // PluginView 契约
  g.__rcPluginV4__ = g.__rcPluginV4__ || {}
  g.__rcPluginV4__[NAME] = { pages: [{ path: '', title: 'Uptime' }], mount }
}
if (typeof window !== 'undefined') register(window)
```

ctx 提供: `invoke(iface, params, {timeoutMs})` / `on/emit` / `toast(msg, kind)` / `navigate(to)` / `plugin{name}`。
**只允许 ctx.invoke 调后端**; 禁止直连插件端口(插件无端口)。

## 4. 构建前端产物

```bash
node tools/build-plugin-frontend.js <name>     # esbuild 内联 vue → plugins/<name>/assets/plugin.js
```

## 5. systemd 单元(宿主)

```ini
[Unit]
Description=RainCough Plugin <name> (v4, portless)
After=network.target raincough.service
Wants=raincough.service

[Service]
Type=simple
User=f
WorkingDirectory=/home/f/raincough-dev/plugins/<name>
ExecStart=/usr/bin/python3 server_v4.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`sudo systemctl enable --now plugin-<name>.service`。

## 6. 上传与部署(宿主)

```bash
# 逐文件上传(host 无 fresh web 源, 前端必须本地构建后上传):
#   plugin.json server_v4.py rcplugin.py frontend/plugin.js assets/plugin.js
# 然后:
sudo systemctl restart plugin-<name>.service
```

## 7. 验收清单(每插件)

1. `systemctl is-active plugin-<name>.service` = active。
2. 「服务健康中心」出现该插件, status=online(18 提供方)。
3. 「接口总览」出现 `plugin.json` 全部接口, 试调用成功。
4. `/api/plugins/<name>/assets/plugin.js` → 200; `/plugin/<name>` 页面渲染、能调 ctx.invoke。
5. 自愈: `kill <MainPID>`(查 `systemctl show -p MainPID`) → 服务健康短暂离线 → systemd 拉起 → 自动重连恢复。
